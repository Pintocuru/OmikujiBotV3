# README テンプレート・部品の編集ルール（生成AI向け）

配置: `development/conventions/readme-template-rules.md`
（`root-readme.md` の「Obsidian テンプレートを使う README」節からここへ誘導する）

Obsidian の Templater と `docs/src/expandEmbeds.js` で README を生成する際のルール。

## 1. 用語とファイル種別

- **README テンプレート**: `docs/**/README.template.<lang>.md`。製品ごとの README の元。
- **部品**: `docs/template/<lang>/` 配下の md。README テンプレートが `![名前](パス)` で展開する。
- **Section**: ファイル名が `Section.md` で終わる部品。見出し（H2、必要なら H3）を含み、そのまま README のセクションになる。全製品で同じ構成の内容（FAQ・トラブルシューティング）に使う。
- **Page**: ファイル名が `Page.md` で終わる部品。README からリンクで開く単独ページで、埋め込まない。
- **生成物**: `README.md` / `README.<lang>.md`。直接編集しない（再生成で上書きされる）。

## 2. 基本原則

1. **日本語（jp）が正。** `docs/template/en/` と、各製品の英語版テンプレート（`README.template.md`）は読まない・編集しない。英語版は日本語版の完成後に作り直す。
2. 生成物（`README.md` / `README.<lang>.md`）は直接編集しない。`expandEmbeds` が上書きする。編集対象はテンプレートと部品。
3. 部品は複数の製品から埋め込まれる。部品を変更する前に、`docs/` 内の全ての参照元を調べて報告する。
4. 迷ったら変更せず、報告する。

## 3. 作業の進め方

### 調査段階（ファイルを変更しない）

- 対象の `README.template.ja.md` を全文読む。
- `![名前](*.md)` の埋め込み先を全て読む。
- 各部品の役割、掲載条件、参照元を整理して報告する。

### 編集段階（承認後）

- 依頼文に「校正」とあれば**校正モード**、「編集」とあれば**編集モード**。指定がなければ校正モード。

## 4. 校正モードで直してよいもの・いけないもの

### 直してよいもの

- 誤字脱字、半角・全角、句読点、明らかな表記ゆれ。

### 直してはいけないもの（気づいたら報告のみ）

- 埋め込み記法、パス、alt 文字、Templater タグ（`<% %>` / `<%* %>`）、画像リンク。
- 見出しの文言とレベル（他の README からアンカーで参照されている）。
- `(TODO:…)` の補完。
- ライセンス・免責・クレジットの文言。
- ファイル名の変更、部品の統合・削除・移動。
- 製品固有の文言を共有部品へ追加すること。
- 製品名、URL、バージョン番号、日付、バッククォート内の文字列（正規表現など）、バックスラッシュのエスケープ。

## 5. 見出し

- **見出し行（`#` で始まる行）を書けるのは Section と Page だけ。** それ以外の部品には書かず、README テンプレートが書く。見出しが部品にあるのかテンプレートにあるのかは、ファイル名の末尾（`Section` / `Page`）で分かる。
- Section を埋め込むときは、テンプレートに見出しを書かない（Section の見出しと重複する）。Section は H2 で始め、中に H3 を持ってよい。
- Section・Page 以外の部品内の小タイトルは太字（`**…**`）にする。同じ階層の見出しが並ぶ内容は、部品を分ける。
- Page は先頭に見出しを持つ。
- 見出しの文言は他の README からアンカー（`#…`）で参照されることがある。変更するときは参照元も確認する。
- **例外**: `installation_VersionUp` は、埋め込み（OmikujiBot）とリンク（ConfigEditor ほか）の両方で使う。リンク先では見出しなしで表示される。

## 6. 部品の作り方・扱い方

- **部品は入れ子にしない（Section を含め、部品の中に `![](*.md)` を書かない）。** そのため、Section の中の一文が別の部品と重複してよい。
- 全製品で構成が同じ内容だけを Section にする。製品ごとに構成が違うもの、同じ文面を複数の Section が持つことになるもの（ライセンスなど）は、Section にしない。
- 文の断片のような、単独で意味の通らない部品を作らない。すでに存在する断片部品（例: `intro_11`、`intro_12`）を見つけた場合は、校正で無理に文を完成させず、参照元を確認したうえで**削除案件**として報告する。
- 部品は複数の製品から使われる。製品固有の内容は README テンプレートに書く。
- 同じ役割の部品を新しく作らず、既存の部品を再利用する。
- 古い・重複した部品を見つけたら、削除せず「整理候補」として報告する。

## 7. 埋め込みとリンク・パスの記法

- `![名前](x.md)`（先頭に `!`）は部品の**埋め込み**で、生成時に展開される。alt の「名前」は展開時に捨てられ、識別用のラベルでしかない。
- `[文字](x.md)`（`!` なし）は**リンク**で、展開されずそのまま残る。FAQ・トラブルシューティングの質問一覧（Page へのリンク）はこの形が正しい。
- 埋め込みをリンクに、リンクを埋め込みに書き換えない。

### パス表記の統一ルール

現状の相対パス・ファイル名のみ・ルート絶対の混在を解消するため、新規作成・整理時は以下に統一する（既存の書き方は勝手に変えず、指示があった場合のみ統一する）。

| 種類                                  | 書き方                                                       |
| ------------------------------------- | ------------------------------------------------------------ |
| README テンプレートからの部品埋め込み | `../../template/jp/<category>/<file>.md`                     |
| 他の README・ドキュメントへのリンク   | ルート絶対（`/core/…` など）                                 |
| 画像                                  | 画像を書くファイルからの相対パスで `docs/images/` 直下を指す |

### 画像パスの事情

部品の画像は `../../../images/xxx.webp` のような相対パスで書く（深さは部品の置き場所で変わる）。GitHub 上で部品や README のプレビューに画像を表示するための対策である。

- 画像は `docs/images/` 直下のみ使える。ウィキリンク形式（`![[…]]`）や他のフォルダの画像は `expandEmbeds` がエラーにして生成を中止する。
- 画像のファイル名と `../` の数を変更しない。

## 8. ファイル命名規則

- 形式: `<category>_<内容を表す英語名>.md`（PascalCase、番号なし）。
- `<category>` はフォルダ名と同じ小文字。`_common` 内は `common_` とする。
- 例: `faq_OneComme.md`、`usage_FirstCounter.md`、`license_App.md`
- **Section は末尾に `Section`、Page は末尾に `Page` を付ける**（例: `faq_OmikujiBotSection.md`、`faq_GiftPage.md`）。FAQ とトラブルシューティングの Page は、質問の種類ごとのサブフォルダに置く。
- 改名・移動・削除・統合の前に、`docs/` 内の全ての参照元（README テンプレート、部品、`README.special.md` など）を調べて一覧で報告し、承認を得てから実施する。

## 9. 変更不可のファイル

- `docs/template/jp/installation/Installation_31_OBS33-install-guide.md`
  - 一般公開済みのため、**ファイルの変更・削除・改名・移動をしない。フォルダ（`installation/`）も変更しない。**
  - 名前を変えた新しいファイルを作成するのは許可する（元のファイルは残す）。

## 10. README の構成

掲載順は固定。製品に該当しないカテゴリは省略してよい。省略する前に、そのカテゴリの既存部品の内容を確認する。共通部品があれば再利用する。

| 順序 | カテゴリ               | フォルダ          | 役割                                                                   |
| ---: | ---------------------- | ----------------- | ---------------------------------------------------------------------- |
|    1 | コモン                 | `_common`         | 全 README 共通の固定リンク・連絡先（定義は整理中。エージェントに一任） |
|    2 | はじめに               | `intro`           | 簡単な紹介、注意点、免責                                               |
|    3 | 機能説明               | `features`        | **機能紹介**。何ができるか、どんな場面で役立つか                       |
|    4 | インストール           | `installation`    | わんコメへの導入、OBS への追加                                         |
|    5 | つかいかた             | `usage`           | **導入時の使い方**。発動条件、テスト方法など                           |
|    6 | カスタマイズ           | `customization`   | エディターの説明                                                       |
|    7 | よくある質問           | `faq`             | 質問一覧（本文は Page へのリンク）                                     |
|    8 | トラブルシューティング | `troubleshooting` | 表示されない、音が出ない等（本文は Page へのリンク）                   |
|    9 | 動作環境               | `requirements`    | **未作成**。わんコメ必須は共通。自作プラグインが必須の製品がある       |
|   10 | クレジット             | `credits`         | イラスト・音源、素材の取り扱い                                         |
|   11 | ライセンス             | `license`         | アプリ本体とパッケージデータ                                           |
|   12 | 寄付                   | `donation`        | 要否を検討中                                                           |

- `roadmap` はカテゴリから外す（README に不要、翻訳も不要）。
- Features と Usage は内容を混ぜない。

## 11. ライセンスの記述

- アプリ本体は **Apache 2.0**（今バージョンから。前バージョンは配布不可）。`license_App.md`（旧 `license_11_LicenseApp`）の記述が正。
- 「アプリ本体は再配布禁止」と書かれた古い記述を見つけたら、直さず報告する。
- パッケージデータのライセンスは製品ごとに異なる。変更しない。
