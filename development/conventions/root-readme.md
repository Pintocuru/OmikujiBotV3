# README・構成ドキュメントの方針

- ルートの README はプロジェクトの概要と入口を担い、詳細な設計・処理説明は `docs/architecture/` に分ける。
- `docs/core/` は利用者向け説明、`docs/conventions/` は恒久的な開発方針、`docs/work/` は一時的な作業記録に使う。
- README は簡潔にし、詳細が必要な項目から関連文書へリンクする。
- ドキュメントは実装・設定・既存資料を確認して書く。確認できた事実、設計意図、将来構想を区別し、不明点を推測で補わない。
- パスやリンクは実在を確認する。コード例やコマンドは現行構成と一致させる。
- 記載項目を機械的に埋める必要はない。対象に必要な情報だけを書く。
- 日本語版と英語版がある場合は、概要・機能・構成に食い違いがないようにする。
- ドキュメント作業では、依頼がない限りアプリケーションコードや設定の動作を変更しない。

## Obsidian テンプレートを使う README

- `README.template.<lang>.md` は、Obsidian の Templater とユーザースクリプト `expandEmbeds` を使って README を生成するテンプレート。
- `![](画像パス)` は画像の埋め込み、`![部品名](Markdownファイル)` は別の Markdown 部品の展開に使用する。
- Templater の実行タグや埋め込み記法を、通常の Markdown リンクへ不用意に書き換えない。
- 生成後の `README.md` / `README.<lang>.md` は、GitHub で表示できる通常の Markdown とする。
- インストール手順などの共通説明は、既存の部品を利用し、各 README で重複して記述しない。
- 部品・テンプレートの編集、命名、見出しのルールは [readme-template-rules.md](./readme-template-rules.md) に従う。
