# README・構成ドキュメントの方針

- ルートの README はプロジェクトの概要と入口を担い、詳細な設計・処理説明は `docs/architecture/` に分ける。
- `docs/core/` は利用者向け説明、`docs/conventions/` は恒久的な開発方針、`docs/work/` は一時的な作業記録に使う。
- README は簡潔にし、詳細が必要な項目から関連文書へリンクする。
- ドキュメントは実装・設定・既存資料を確認して書く。確認できた事実、設計意図、将来構想を区別し、不明点を推測で補わない。
- パスやリンクは実在を確認する。コード例やコマンドは現行構成と一致させる。
- 記載項目を機械的に埋める必要はない。対象に必要な情報だけを書く。
- 日本語版と英語版がある場合は、概要・機能・構成に食い違いがないようにする。
- ドキュメント作業では、依頼がない限りアプリケーションコードや設定の動作を変更しない。
