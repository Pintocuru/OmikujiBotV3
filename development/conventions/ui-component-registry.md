# UI 内コンポーネントレジストリ

## 目的

UI の内部で表示コンポーネントをセット単位で登録し、配布構成に応じて利用できるようにする。UI 本体の登録やエディター全体の登録とは責務を分ける。

## 設計上の原則

- 共通レジストリは登録・取得の共通処理を担当し、個別 UI の型やメタ情報の意味を解釈しない。
- UI 固有の型・メタ情報・利用 API は、UI ごとの薄いラッパーなどで管理する。
- 登録情報は、識別 ID、エディター表示名の i18n キー、コンポーネント loader、必要な UI 固有メタ情報を基本とする。
- セットは登録・配布の単位。開発用構成やエディターでは必要なセットを登録し、配布パッケージでは実際に必要なセットを登録する。
- 登録 API や配置は既存コードとの整合を優先する。文書にある例をそのまま固定仕様として扱わない。

## ID と型

- ID は安定した文字列とし、同一 UI 内で重複させない。登録順による上書きを前提にしない。
- 保存データの ID は、未同梱・将来追加の ID を保持できる型にする。既知 ID の型検査は登録側で行う。
- ID の形式や型定義の配置は、現行スキーマ・登録実装と整合させる。

## 未登録・読み込み失敗

- 未登録 ID を読み込み時に別 ID へ書き換えたり、設定データから削除したりしない。
- 配信画面での代替表示や通知方法は UI の性質に応じて決める。設定を黙って変更しない。
- エディターでは、利用者が未登録状態を認識して修正できる表示を用意する。
- 未登録と読み込み失敗は、可能なら区別して扱う。

## 変更時

既存実装・型・配布エントリを確認してから変更する。共通レジストリを変更する場合は、利用する全 UI と配布構成への影響を確認する。細かな実装手順はこの規約に固定せず、必要な作業文書に記載する。
