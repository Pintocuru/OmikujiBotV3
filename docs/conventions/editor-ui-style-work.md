# エディター UI スタイル統一作業 — OmikujiBotV3

`src/editor/` のボタン、アイコン、`title`、DaisyUI tooltip の使い方を段階的に統一するための作業指示書・引き継ぎ記録。

## 0. 作業開始時に読むもの

1. `docs/conventions/editor-ui-style.md` — 確定済みの恒久ルール
2. 本書 — 作業範囲、進め方、進捗、未解決事項

**恒久ルールを優先する。** 本書に古い記述や矛盾があれば、恒久ルールに合わせて本書を更新する。実コードが規約と異なる場合、実コードを根拠に規約を勝手に読み替えず、差異として扱う。

## 1. 目的

- `src/editor/` のボタンのサイズ・色・アイコンを一貫させる。
- `title` と DaisyUI tooltip の役割を統一する。
- tooltip が画面端や親コンテナで隠れる問題を減らす。
- 一括置換で意図しない UI 変更を起こさず、操作の意味を確認しながら段階的に進める。

## 2. 確定した仕様

### 2.1 ボタン

- 標準サイズ: `btn-sm`
- `btn-primary`: 保存・確定など、重要な主操作だけ
- `btn-neutral`: 通常操作
- `btn-ghost`: キャンセル・閉じる・補助操作
- `btn-error`: 削除などの危険操作
- `btn-warning`: 注意が必要な操作
- `btn-outline`: 役割とは独立した見た目の修飾。役割クラスと併用可能

### 2.2 アイコン

- 標準サイズ: `w-4 h-4`
- アイコンとテキストの間隔: `gap-2`
- アイコンのみ: `btn-square` または `btn-circle`
- アイコンのみのボタン: `aria-label` 必須

### 2.3 title / tooltip

- アイコンのみ、または短い操作説明が必要: DaisyUI tooltip
- 省略文字列・ファイル名などの内容確認: `title`
- 通常のテキスト付きボタン: 原則どちらもなし
- `title` と tooltip は原則併用しない

### 2.4 tooltip の位置

- 基本は `tooltip-top`
- 左端で左側に表示領域がない: `tooltip-right`
- 右端で右側に表示領域がない: `tooltip-left`
- 上端で上側に表示領域がない: `tooltip-bottom`
- 下端で下側に表示領域がない: `tooltip-top`
- 固定のピクセル境界は設けず、実際の表示領域に合わせて判断する。
- 親要素の `overflow` と `z-index` も確認する。DaisyUI が自動で位置を反転する前提にしない。

## 3. 作業対象と対象外

- 対象: `src/editor/` 内で、上記規約に関係するボタン・アイコン・補足説明。
- 専用スタイルを持つ `tabs` / `tab`、DaisyUI `menu` などは、通常の `btn` と同じ方法で統一しない。
- エディター外の UI は、別途依頼がない限り対象に含めない。
- 既存コンポーネントの責務や操作仕様を変える作業ではない。見た目の統一に必要な範囲に限定する。

## 4. 進め方

### 4.1 着手前

1. §0 の文書を両方読む。
2. 対象ディレクトリの構成と既存コンポーネントを確認する。
3. 対象をディレクトリまたは機能単位に分け、変更候補を一覧化する。
4. 既存の共通ボタン・ダイアログ部品があれば、利用箇所と責務を確認する。
5. 変更対象と対象外を明確にしてから着手する。

### 4.2 実装中

- 一度に `src/editor/` 全体を機械的に置換しない。
- 1つのまとまりを変更したら、差分と表示を確認してから次へ進む。
- ボタンの色は、クラス名だけで決めず、操作内容と画面内での重要度を確認して決める。
- サイズ指定がないボタンは、配置や共通コンポーネントの仕様を確認したうえで、原則 `btn-sm` に揃える。
- `btn-outline` は必要性を確認して残す。単純に削除・追加しない。
- Tooltip は実際の配置を確認し、表示領域が足りる方向を選ぶ。画面端の判断を固定ピクセル値にしない。
- 不明点や仕様変更につながる判断が出た場合は、独断で進めず質問する。
- 既存の操作・イベント・保存処理・アクセシビリティを壊さない。

### 4.3 検証

変更した単位ごとに、可能な範囲で次を確認する。

- TypeScript / lint など、プロジェクトで定められた検証
- ボタンの色・サイズ・アイコン位置
- tooltip の表示位置、画面端での切れ、親要素の clipping、重なり順
- アイコンのみのボタンの `aria-label`
- 通常操作・キャンセル・危険操作が見分けられること
- 変更前の操作が維持されていること

実行できなかった検証は、成功したように記載せず「未実施」とする。

## 6. 引き継ぎルール

- 作業再開時は、必ず §0 の2文書を読む。
- 過去の会話だけを根拠にせず、対象ファイルの現在の内容を読み直す。
- 未確認の実装や仕様を推測で補わない。確認できない点は「未確認」と記録する。
- 広範囲を一度に変更せず、ディレクトリまたは機能単位で進める。
- 判断が必要な事項は、確定済み仕様を変えない範囲なら規約に従う。規約の変更や操作仕様の変更が必要なら、作業を止めて確認する。
- 作業終了時は、変更したファイル、変更内容、検証結果、未解決事項、次の作業を §5 に記録する。
- 恒久ルールを変更した場合は、本書との整合性も同時に確認する。
- コミット・push は依頼者の明示的な許可がある場合だけ行う。
