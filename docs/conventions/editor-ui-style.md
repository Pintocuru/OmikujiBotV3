# エディター UI スタイル規約 — OmikujiBotV3

`src/` の UI(エディター・各 UI プラグイン)のボタン、アイコン、補足説明の見た目と使い方を統一するための恒久ルール。

## 1. 適用範囲

- 原則として `src/` 内の UI に適用する。
- DaisyUI の `btn` を使うボタンが対象。
- DaisyUI の `tabs` / `tab`、`menu` など、専用の構造・スタイルを持つ UI は、無理に `btn` に置き換えない。
- 規約と既存コンポーネントの責務が競合する場合は、既存コンポーネントの役割を確認してから判断する。

## 2. ボタンの基本形

- DaisyUI の `btn` をベースクラスとして使用する。
- 標準サイズは **`btn-sm`**。
- サイズ指定のないボタンを見つけた場合は、配置領域や既存コンポーネントの仕様を確認し、原則 `btn-sm` を付ける。
- `btn` / `btn-sm` などのサイズを、同じ画面内で理由なく混在させない。
- `btn-lg` など標準外のサイズは、明確な視覚的理由がある場合に限る。

## 3. 色・役割

色はボタンの操作上の役割で選ぶ。重要度の低い操作に `primary` を多用しない。

| クラス                | 用途                                                               |
| --------------------- | ------------------------------------------------------------------ |
| クラス                | 用途                                                               |
| ---                   | ---                                                                |
| `btn-primary`         | 保存・確定など、その画面で特に重要な主操作                         |
| `btn-secondary`       | 追加・実行など、一般的な通常操作の基本候補                         |
| `btn-info`            | 情報の確認・案内に関係する操作                                     |
| `btn-accent`          | 画面内で視覚的に区別したい、特別な操作                             |
| `btn`（色クラスなし） | 意味上の色付けが不要な、標準的で控えめな操作                       |
| `btn-neutral`         | neutral の配色が適切で、背景とのコントラストを確認できた場合に限定 |
| `btn-ghost`           | キャンセル・閉じる・補助操作                                       |
| `btn-error`           | 削除など、取り消しに注意が必要な危険操作                           |
| `btn-warning`         | 注意を促す必要がある操作                                           |

- `btn-primary` は「実行する操作全般」を意味しない。画面内で重要な主操作に限定する。
- 通常操作では `btn-secondary` を優先候補とし、情報に関係する操作には `btn-info`、特別に区別したい操作には `btn-accent` を検討する。クラスの意味と操作内容を一致させる。
- 色クラスを付けない `btn` も有効な選択肢とする。色による意味付けが不要な場合に使用し、DaisyUI 標準のボタン配色を利用する。
- `btn-neutral` は通常操作の一律指定にしない。特に dark 系テーマでは背景に埋もれる場合があるため、使用箇所の背景と通常時のコントラストを確認する。
- すべてのボタンで、ホバー時に色または明度などの見た目が変化し、操作対象であることを視覚的に判別できる状態にする。DaisyUI 標準の hover 表現を不用意に打ち消さず、独自スタイルを追加・上書きする場合も通常時との差が分かるようにする。
- light / dark の両方で通常時とホバー時の見え方を確認する。特定テーマや親要素の背景色によりコントラストが不足する場合は、別の意味クラスまたは色クラスなしの `btn` を選ぶ。
- 破壊的操作であることが明確な場合は、通常操作と区別できる色を使う。
- 色だけに意味を依存させず、操作名やアイコンも分かりやすくする。

## 4. `btn-outline` の扱い

- `btn-outline` は操作の役割ではなく、見た目を変える修飾クラスとして扱う。
- 必要に応じて役割クラスと組み合わせる。
  - 通常操作: `btn-neutral btn-outline`
  - 重要操作: `btn-primary btn-outline`
- `btn-outline` を付けること自体を、ボタンの重要度や操作種別の表現に使わない。

## 5. アイコン付きボタン

- アイコンの標準サイズは **`w-4 h-4`**。
- アイコンとテキストの間隔は **`gap-2`** を標準とする。
- アイコンとテキストを横並びにする場合は、ボタン側に `gap-2` を指定する。
- アイコンのみのボタンは、形状に応じて `btn-square` または `btn-circle` を使う。
- アイコンのみのボタンには、用途を伝える `aria-label` を必ず付ける。
- アイコン名はプロジェクトで利用可能な Lucide アイコンから選ぶ。存在を確認できないアイコン名を推測で使わない。

## 6. `title` と `tooltip`

用途を分け、原則として同じ要素に併用しない。

| 用途                                                     | 使用                 |
| -------------------------------------------------------- | -------------------- |
| アイコンのみで意味が分かりにくいボタン                   | DaisyUI `tooltip`    |
| 操作内容について短い説明が必要なボタン                   | DaisyUI `tooltip`    |
| 省略された文字列・ファイル名など、表示内容そのものの確認 | HTML `title`         |
| 通常のテキスト付きボタン                                 | 原則どちらも付けない |

- `tooltip` は操作の説明に使い、長文のヘルプや複数段落の説明には使わない。
- `title` は、表示中の文字列だけでは内容を確認できない場合などに使う。
- `title` と `tooltip` を併用すると説明が重複するため、原則禁止する。
- アイコンのみのボタンでは、`tooltip` の有無にかかわらず `aria-label` を付ける。

## 7. Tooltip の表示位置

DaisyUI の tooltip は、画面端の空き領域を自動判定して表示位置を反転するものではない。表示位置はレイアウトを確認して明示する。

- 基本位置は **`tooltip-top`**。
- 左端付近で左側に十分な表示領域がない場合は `tooltip-right`。
- 右端付近で右側に十分な表示領域がない場合は `tooltip-left`。
- 上端付近で上側に十分な表示領域がない場合は `tooltip-bottom`。
- 下端付近で下側に十分な表示領域がない場合は `tooltip-top`。
- 上記は固定ピクセル距離で判定しない。実際の tooltip の幅、ボタン位置、親コンテナ、画面サイズを見て、表示できる方向を選ぶ。
- 画面端だけでなく、親要素の `overflow` や `z-index` によって tooltip が切れないかも確認する。
- 表示方向を選べない共通コンポーネントでは、利用側が方向を指定できる設計を優先する。自動反転するものとして扱わない。

## 8. 変更時の確認

- 既存ボタンを変更する場合は、見た目だけでなく操作の重要度・危険性・補助性を確認してクラスを選ぶ。
- `tabs` / `menu` など専用 UI のスタイルを、見た目だけを理由に `btn` へ置き換えない。
- Tooltip を追加・変更した場合は、通常表示に加えて画面端、親コンテナの clipping、重なり順を確認する。
- アイコンのみのボタンは、アクセシブルな名前(`aria-label`)があることを確認する。
