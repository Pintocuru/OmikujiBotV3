# 日本語 UI 文言規約 — OmikujiBotV3

`src/i18n` の日本語文言を、新規追加・修正するときの恒久ルール。

## 1. 適用範囲

- 対象は `src/i18n` にある日本語（`ja`）の文言。
- 英語（`en`）、翻訳キー、ファイル構成、データ構造は対象にしない。
- 日本語以外の UI 文言や、`src/i18n` 以外の文章には適用しない。
- 本規約は原則として必ず守る。例外が必要な場合は、理由を明確にする。

## 2. 基本文体

- です・ます調を基本にせず、常体・体言止めを使う。
- ラベルや短い説明は、名詞または短い表現を優先する。
- 文脈から明らかな主語・対象・説明を繰り返さない。
- 省略によって意味が曖昧になる場合は、省略しない。
- 短さだけを優先した不自然な日本語や、硬すぎる表現は避ける。

| 用途 | 基本形 | 例 |
| --- | --- | --- |
| ラベル | 名詞・短い語句 | `色の一覧` |
| ボタン・操作ラベル | 動作を簡潔に表す | `保存` / `設定` |
| 説明文 | 簡潔な常体・体言止め | `true のときに発動` |
| Tooltip | 原則1文の短文 | `ほかのおみくじの発動を制限` |
| 警告・注意 | 正確さを優先した文章 | 必要な条件・影響・対処を省略しない |
| エラー通知 | 状況と必要な対処を簡潔に示す | 原因や操作結果を誤解させない |

## 3. 短縮の方針

- 意味を保てる範囲で積極的に短縮する。
- 冗長な前置き、丁寧語、重複する主語・対象、不要な補足を取り除く。
- 語順や言い回しは、意味を維持できるなら変更してよい。
- 同じ内容を伝えられる場合は、短く自然な表現を選ぶ。
- 文字数を減らすために、必要な条件・対象・結果を削らない。
- 文字数の一律上限は設けない。表示領域に応じて簡潔さを調整する。

## 4. Tooltip・説明文

- Tooltip は表示領域が限られるため、原則1文・短文にする。
- Tooltip に長いヘルプや複数の説明を詰め込まない。
- 詳細な説明が必要な場合は、Tooltip だけで完結させず、適切な説明領域に分ける。
- 説明文も簡潔にするが、Tooltip と同じ文字数制限を一律には適用しない。
- 文章を短くしても、何についての説明か分かる状態を保つ。

## 5. 警告・注意・エラー

- 警告・注意書きは短さより意味の正確さを優先する。
- 操作の条件、影響、取り消し可否、必要な対処など、判断に必要な情報を残す。
- 誤解や操作ミスにつながる省略をしない。
- 丁寧語を減らす場合も、強すぎる命令や冷たい表現にならないようにする。

## 6. 句読点・表記

- ラベル、ボタン名、短い語句には句点（。）を付けない。
- 説明文・警告など、文章として成立する文には必要に応じて句点を付ける。
- 読みやすさを優先し、漢字に偏らない。補助的な語は適度にひらがなで表記する。
  - 例：`出来る` → `できる`、`下さい` → `ください`
- 漢字・ひらがなの選択は、短縮だけでなく読みやすさで判断する。
- 三点リーダーなどの記号は、同じ用途で表記を揃える。

## 7. 用語・技術表記

- 同じ機能・概念には同じ用語を使い、表記揺れを作らない。
- 既存のドメイン用語は `docs/conventions/naming.md` の用語表を優先する。
- 短縮のために別の呼び方を作ったり、既存用語を独自に言い換えたりしない。
- `true` / `false` など、コードや UI と対応する既存の技術用語は原則維持する。
- 技術用語を無理に日本語化しない。必要に応じて既存の英語表記・カタカナ表記を使う。
- 用語の意味や表示名を変更する必要がある場合は、関連する規約・実装との整合を確認する。

## 8. 翻訳文の構造

- 変数・プレースホルダー・補間式・HTML タグ・改行など、翻訳文に含まれる構造を維持する。
- 変更対象は原則として文章部分のみとする。
- `{name}` や `{count}` などのプレースホルダー名・個数・役割を変更しない。
- タグ、属性、改行、エスケープなどを削除・追加・変更しない。
- 翻訳キーやデータ構造を変更しない。
- 文中のプレースホルダー位置を変える必要がある場合も、構造・表示結果への影響を確認し、文章の短縮だけを理由に移動しない。

## 9. 見直し・追加時の確認

日本語文言を新規追加・修正するときは、次を確認する。

- [ ] です・ます調に頼らず、常体・体言止めを基本にしている。
- [ ] 意味を保てる範囲で簡潔にしている。
- [ ] 主語や対象など、文脈から明らかな情報を重複させていない。
- [ ] Tooltip は原則1文の短文になっている。
- [ ] 警告・注意・エラーの意味や必要な情報を削っていない。
- [ ] ラベル・ボタンなどの短い表現に句点を付けていない。
- [ ] 漢字に偏らず、読みやすい表記になっている。
- [ ] 既存用語・技術用語と表記が統一されている。
- [ ] プレースホルダー・タグ・改行などの構造を維持している。
- [ ] 英語・翻訳キー・データ構造を変更していない。

## 10. 判断に迷った場合

- 短さと自然さが両立しない場合は、自然さと意味の明確さを優先する。
- 短縮によって誤解が生じる場合は、短縮しない。
- 用語の判断は `docs/conventions/naming.md` を確認する。
- Tooltip の表示位置・幅・ clipping など、表示上の問題は文言の短縮だけで解決しようとせず、UI 側の実装も別途確認する。
