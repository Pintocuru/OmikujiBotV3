## 判定式（コメントの発動条件）

### 概要

- **目的**: 「式が成立したときだけ発動する」条件を、数式で自由に書けます。チャットワードや役職などの標準の条件では書けない、細かな条件を指定したいときに使います。
- **使える場所**: コメントイベントの**追加発動条件**、おみくじ項目の**発動条件**
- **上級者向けの機能です。** 標準の条件で足りるときは、そちらを使ってください。
- 判定式は**値を読むだけ**です。変数を書き換えるのは [評価ブロック](./VariablePlaceholder.md) です。

### 基本的な書き方

比較や論理演算の式を書きます。**結果が `true` のときだけ**発動します。

```text
lc >= 10
```

- 結果が数値や文字列になる式（`lc + 1` など）は `false` として扱われます。
- 評価できない式（書き間違いなど）も `false` として扱われ、エラーが 1 回通知されます。

---

### 使える値

#### 標準値

コメントイベントの本文で使う `<<lc>>` などと同じ値が、そのまま使えます。

| 名前        | 意味                                              | 型   |
| ----------- | ------------------------------------------------- | ---- |
| `user`      | コメントしたユーザーの表示名（`userName` も同じ） | 文字 |
| `userId`    | コメントしたユーザーの ID                         | 文字 |
| `lc`        | この配信枠でのコメント通し番号                    | 数値 |
| `tc`        | そのユーザーの累計コメント数                      | 数値 |
| `price`     | ギフト金額（金額が付かないものは `0`）            | 数値 |
| `giftCount` | ギフトの個数                                      | 数値 |
| `viewer`    | 現在の同時接続数                                  | 数値 |
| `upVote`    | 高評価数                                          | 数値 |
| `follower`  | 登録者数                                          | 数値 |
| `commenter` | 配信内でコメントした累計ユニークユーザー数        | 数値 |
| `syoken`    | 初見さんの数                                      | 数値 |

#### 評価ブロックで作った変数

[評価ブロック](./VariablePlaceholder.md) で作った変数も、変数名をそのまま書いて読めます（読むだけで、書き換えはできません）。

- 標準値と同じ名前の変数がある場合は、標準値が優先されます。
- **未定義の変数は `0` として扱われます。** 変数名の打ち間違いにご注意ください。

---

### 使える演算子と関数

| 種類         | 書き方                                                                  |
| ------------ | ----------------------------------------------------------------------- |
| 比較         | `==` `!=` `>` `>=` `<` `<=`（文字列は `==` `!=` で比較できます）        |
| 論理         | `and` `or` `not`                                                        |
| 四則・剰余   | `+` `-` `*` `/` `%` `^`（べき乗）                                       |
| 条件分岐     | `条件 ? 真の値 : 偽の値`、`if(条件, 真の値, 偽の値)`                    |
| 文字列の連結 | `\|\|`                                                                  |
| 関数         | `min` `max` `pow` `roundTo` `abs` `ceil` `floor` `round` `trunc` `sqrt` |
| 型変換       | `str()` `num()` `bool()`                                                |

- 文字列は `'さくら'` のように、シングルクォート（またはダブルクォート）で囲みます。
- **使えないもの**: 代入（`=`）、複数の式（`;`）、乱数（`rand`）。判定式は読み取り専用です。

#### `<<名前>>` の書き方

`<<lc>>` のように `<<>>` で囲んでも、`lc` と書いても同じ意味です。

```text
<<lc>> > 20      // lc > 20 と同じ
```

変数名の一部に `<<userId>>` などを**埋め込む**と、その値に置き換えてから評価します。ユーザーごとの変数を読みたいときに使います。

```text
SyokenSagi<<userId>> < 3
```

- 埋め込める値は、英数字と `_` だけで構成されたものに限ります。それ以外は評価できず、`false` になります。
- 変数名に埋め込むときは、`<<user>>`（表示名）ではなく `<<userId>>` を使ってください。

### 例

#### コメントの内容・ユーザーで絞る

```text
lc % 100 == 0           // 100 件目、200 件目…のコメントのとき
tc >= 10                // 累計コメント数が 10 回以上のユーザー（常連）
user == 'さくら'        // 表示名が「さくら」のユーザー
price >= 500            // 500 円以上のギフトのとき
```

#### 配信の状況で絞る

```text
viewer >= 100                       // 同時接続数が 100 人以上
upVote > 50 and follower < 1000     // 高評価が 50 を超え、登録者が 1000 未満
```

#### 条件を組み合わせる

```text
(lc >= 10 and tc <= 3) or price > 0   // 序盤の新規ユーザー、またはギフトのとき
not (user == 'ownerName')             // 特定のユーザー以外
```

#### 評価ブロックと組み合わせる（変数を条件にする）

**1 人 3 回まで**にしたい例です。

1. このおみくじのシナリオの最初（遅延 0 秒）に、評価ブロックを置きます。

   ```text
   played_<<userId>> += 1
   ```

2. 判定式に、回数の条件を書きます。

   ```text
   played_<<userId>> < 3
   ```

   3 回引いたユーザーは、4 回目から条件を満たさなくなります。

遅延 0 秒の評価ブロックは、おみくじが発動した瞬間に実行されます。連続でコメントされても、回数を数え損ねません。

**イベントの進行で切り替える**例です。評価ブロックで `stage = 2` のように段階を記録しておき、判定式で `stage == 2` と書くと、その段階のときだけ発動します。

---

### うまく動かないとき

| 症状                       | 考えられる原因                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------- |
| いつも発動しない           | 結果が `true` にならない式（`lc + 1` など）、変数名の打ち間違い（未定義は `0` になる） |
| エラーが通知される         | 構文エラー、`;` や `=` を使っている、埋め込んだ値に英数字と `_` 以外が含まれている     |
| 変数を使った条件が効かない | 評価ブロックが実行されていない、または変数名が評価ブロックと違う                       |
| ユーザー名で比較できない   | `user` は表示名です。ID で比較するなら `userId` を使う                                 |
