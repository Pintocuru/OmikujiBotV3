## 2. 作業方針

監査レポートを修正候補の一覧として利用し、必ず実際のソースコードと照合してください。

レポートの指摘を無条件にすべて修正するのではなく、以下を判断してください。

- 実際にユーザーに表示される文字列か
- 翻訳関数を通す必要がある文字列か
- 既存の翻訳キーで代用できないか
- 日本語・英語の両方に適切な翻訳が存在するか
- 技術用語、固有名詞、データ値、サンプル文字列など、翻訳対象外にすべきものではないか
- 動的キーの場合、実際に生成されるキーが翻訳定義に存在するか
- 複数形、日付、数値、単位などのロケール依存処理が適切か

**単純な文字列置換で済ませず、既存の i18n 設計に合わせて修正してください。**

## 3. 翻訳システムの制約

このプロジェクトは Vue 3 + TypeScript + vue-i18n を使用しています。

- 対応ロケール: `ja` / `en`
- デフォルト・フォールバック: `ja`
- 翻訳定義の集約: `src/i18n/editor/messageModules.ts`
- 翻訳定義: `src/i18n/editor/` 以下
- 翻訳モジュールは `messageModules.ts` に明示的に登録する構造です。

翻訳ファイルを新規作成する場合は、必ず `messageModules.ts` への登録も確認してください。

既存の翻訳キーを再利用できる場合は、同じ意味のキーを重複して追加しないでください。

翻訳キーの命名規則や階層構造は、既存の翻訳定義に合わせてください。

日本語と英語の翻訳オブジェクトは、キー構造を一致させてください。

## 4. 修正対象

監査レポートに記録された以下の問題を対象とします。

- missing key
- hardcoded string
- empty or untranslated value
- dynamic key
- locale formatting
- 要確認として記録された項目

Batch 28・29 は Batch 34 と重複するため対象外です。

また、レポートに記載されていない箇所でも、対象範囲内で明らかな翻訳漏れを発見した場合は修正候補に含めてください。

ただし、監査対象外のディレクトリへ無制限に調査範囲を広げないでください。

### 特に注意する項目

- Batch 05 と Batch 30 にある、複製名の「(コピー)」に関する指摘は同じ仕様に関係する可能性があります。重複した翻訳キーを作らないでください。
- Batch 30 の `useDataIO.ts`、`useDataMerge.ts` にあるエラー・成功通知の文言を確認してください。
- Batch 33 の `FontFamilyEditor` のプレビュー用サンプル文字列は、実際の翻訳対象かどうかを判断してください。
- Batch 32、34 は検出なしですが、レポートの対象範囲を勝手に変更しないでください。
- Batch 31 は検出なしです。

## 5. 修正時の注意

### 既存の動作を変えない

今回の目的は翻訳対応です。

- データ構造を変更しない
- 保存形式を変更しない
- API の仕様を変更しない
- ストアの動作を変更しない
- コンポーネントの表示・操作仕様を変更しない
- 既存のコメントを理由なく削除しない
- 不要なリファクタリングを行わない

翻訳対応に必要な最小限の変更にしてください。

### 動的な文字列

文字列連結やテンプレートリテラルを安易に翻訳関数で囲まないでください。

必要に応じて vue-i18n の named interpolation などを使用し、自然な日本語・英語になるようにしてください。

### 複製名などの保存データ

複製名のように翻訳結果がデータとして保存される場合は、UI表示用の翻訳と同じ扱いにしないでください。

既存データとの互換性や、言語を切り替えた際の挙動を確認し、データ仕様を不用意に変更しないでください。

## 6. 作業手順

以下の順番で作業してください。

1. 監査レポートをすべて確認する。
2. 検出項目をファイル・問題種別ごとに整理する。
3. 重複指摘を統合する。
4. 既存翻訳定義との重複・不足を確認する。
5. 修正方針を決める。
6. ソースコードと翻訳定義を修正する。
7. 日本語・英語のキー構造を照合する。
8. lint、型チェック、ビルドなど、既存の利用可能な検証を実行する。
9. 修正内容と検証結果を報告する。

修正前に、既存の作業変更を確認してください。ユーザーの変更を上書き・破棄してはいけません。
