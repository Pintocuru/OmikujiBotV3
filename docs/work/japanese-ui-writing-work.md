# 日本語 UI 文言の見直し作業 — OmikujiBotV3

> 状態: **作業中**
> 恒久ルール: `docs/conventions/japanese-ui-writing.md`

`src/i18n` の日本語文言を、恒久ルールに沿って段階的に見直すための作業指示書。

## 0. 作業開始時に読むもの

1. `docs/conventions/japanese-ui-writing.md` — 日本語 UI 文言の恒久ルール
2. 本書 — 作業範囲、進め方、作業記録
3. `AGENTS.md` — リポジトリ共通の作業ルール

恒久ルールを優先する。本書と矛盾する場合は恒久ルールに合わせる。

## 1. 目的

- `src/i18n` の日本語（`ja`）を、簡潔で自然な表現に統一する。
- 文字数の多さによる UI の折り返しや Tooltip の表示上の問題を減らす。
- 意味・操作仕様・翻訳データの構造を変えず、明確に改善できる文言を修正する。
- 意味やニュアンスの判断が必要な箇所は、無理に自動修正せず、依頼者が手作業で判断できるように残す。
- 口調・文体の変更は一律に行わず、一般利用者向けと開発者向けを文言単位で判別して扱う。

## 2. 対象範囲

- 対象: `src/i18n` 内の日本語（`ja`）文言のみ。
- 英語（`en`）、翻訳キー、ファイル構成、データ構造は変更しない。
- `src/i18n` 以外の UI 文言、CSS、Tooltip の配置・幅などの実装は変更しない。
- 対象ファイルや言語の構造は、作業開始時に実際のリポジトリを読んで確認する。ファイル名や構成を推測しない。

## 3. 作業範囲と段階

### 作業1：調査・分類

- `src/i18n` の構成と日本語文言を確認する。
- 冗長な表現、です・ます調、長い Tooltip、表記揺れなどを抽出する。
- 修正候補を次の3種類に分類する。
  - **機械的に修正可能**: 意味が明確で、規約に沿う変更が一意に判断できる。
  - **要注意**: 文脈・機能仕様・用語の確認が必要。
  - **手作業候補**: ニュアンス、説明の正確さ、操作上の意味など、依頼者自身の判断が望ましい。
- 調査結果はファイル単位で整理し、件数と代表例を報告する。
- この段階では原則としてコード・翻訳文を変更しない。

### 作業2：明確な箇所のみ修正

- 作業1で「機械的に修正可能」と分類した箇所を中心に修正する。
- です・ます調の除去、明らかな冗長表現の削除、短いラベルの簡潔化など、意味を維持できる変更を行う。
- Tooltip は短くできる場合に限り、原則1文の短文に整える。
- **一般利用者向け**の文言は恒久ルールに沿って簡潔化・文体調整してよい。
- **開発者向け**（開発用設定、内部仕様、デバッグ、開発者向けヘルプ・コメント等）の文言は、口調や言い回しを原則維持する。明らかな誤字・重複など機械的に直せる箇所だけ修正し、文体変更は手作業候補として報告する。
- 対象が一般向けか開発向けか判別できない場合は変更せず「要確認」に分類する。ファイル全体で一括判断せず、必要に応じて文言単位で分類する。
- 警告・注意・エラーは、条件・影響・対処などの情報を削らない。意味の正確さに確信が持てない場合は変更しない。
- 用語の意味や表記に判断が必要な場合は、独断で統一・変更しない。
- 「要注意」「手作業候補」は原則変更せず、元の文言・修正案・判断が必要な理由を一覧で報告する。
- 修正範囲を広げたり、文章の意味・機能仕様を変更したりしない。
- ファイル単位または小さなまとまりで差分を確認しながら進める。

### 作業3：全体検証（今回は実施しない）

以下は作業2の完了後、別作業として実施する。

- 日本語と英語の翻訳キー対応
- プレースホルダー・タグ・改行・エスケープなどの構造比較
- 型チェック・ビルドなど、プロジェクトで必要な検証
- 実際の UI での折り返し・Tooltip の clipping・表示幅の確認
- 全体の用語統一と文体の最終確認

作業2の終了時に、作業3を実施済みと扱わない。未検証事項を明確に残す。

## 4. 絶対に維持するもの

- 翻訳キー、オブジェクトの階層、ファイル構成
- プレースホルダーの名前・個数・役割
- HTML タグ、属性、改行、エスケープなどの構造
- 英語など日本語以外の翻訳
- UI の操作仕様・機能上の意味

文章の順序変更やプレースホルダー位置の変更も、構造や表示結果への影響があるため、短縮だけを理由に行わない。

## 5. 判断基準

- 恒久ルール `docs/conventions/japanese-ui-writing.md` に従う。
- 短さと自然さが両立しない場合は、自然さと意味の明確さを優先する。
- 警告・注意・エラーは、短縮より正確さを優先する。
- 意味が変わる可能性、機能仕様の理解が必要、用語の正解が不明、複数の修正案があり判断が分かれる場合は変更しない。
- 未確認の内容を推測で補わない。判断できない場合は「未確認」と記録する。
- 一括置換は、対象と結果を限定・確認できる場合を除き行わない。
