# Amidakuji(あみだくじ) 仕様(たたき台)

LiveConsole の `control` カテゴリの画面。別ウィンドウで開き、OBS でキャプチャして配信に映す。
画面のキーは `amidakuji`。置き場所は `src/console/control/Amidakuji/`。

## 表記

- **【決定】**: 方針として決まっていること(ヒアリングで確認済み)。
- **【案】**: たたき台での提案。承認されるまで確定ではない。
- **【保留】**: 実装時に改めて検討する。
- 「OshikuraChain / WordAlchemy に準拠」とあるものは、`../../game/OshikuraChain/SPEC.md` の同名の節と同じ。

## 概要

- 配信者が、**抽選ツール**として使う。参加者(縦線)とゴール(当たり・はずれ)を用意し、横線を引いて、結果を発表する。【決定】
- 参加者は、**コメントで募集**する。配信に来ていない人も、**手動で追加**できる。【決定】
- ゴールは**任意に入力**できる(プレゼント抽選など、臨機応変に使う)。【決定】
- 横線は、**自分で引く**・**自動で引く**・**両方**を選べる。【決定】
- 縦線は **30 本程度**を想定する。多い場合は、**拡大表示**で対応する。【決定】
- 結果の発表は、**全員同時**と**一人ずつ**の両方を選べる。【決定】
- 画面は、別ウィンドウを OBS でキャプチャして配信に映す。【決定】

## 遊びの流れ

1. **準備**: 参加者を集める(コメント募集・手動追加)。ゴール(当たりリスト)を入力する。
2. **横線**: 自分で引く、または自動で引く(併用できる)。
3. **発表**: 全員同時、または一人ずつ、線を辿ってゴールを明かす。
4. **結果**: 参加者とゴールの対応を一覧で表示する。「もう一度」で準備に戻る。

状態は、画面(composable)が持ち、保存はしない。子コンポーネントには、`provide` / `inject` で渡す(props・emit の素通しをしない)。【決定】

## 画面の登録

- `src/console/maps/ConsoleViewMap.ts` に、1 項目を足す。【決定】

  ```ts
  amidakuji: {
    label: 'あみだくじ',
    icon: 'Shuffle', // lucideIconMap にあるものから選ぶ。なければ追加する
    category: 'control',
    launch: 'window',
    windowSize: { width: 960, height: 540 }, // 【案】 16:9 (OBS キャプチャ向け)
  },
  ```

- 並び順は、`control` の中で、`usersConsole` の後ろ。【案】
- loader は、`src/register/registerConsoleViews.ts` に 1 行足す。
- `category` と `launch` は、独立している。`control` カテゴリで `window` 起動にするのは、「抽選ツールだが、OBS でキャプチャする」ため。【決定】

## 参加者

### コメントでの募集

- **募集の開始・締切**のボタンを置く。募集中のコメントだけが、参加者になる。【案】
- 1 ユーザー 1 本(`userId` で重複を除く)。表示名はコメントのユーザー名。【案】
- 参加者の一覧から**削除した人は、コメントしても再参加しない**。(手動追加した人は対象外)。【決定】
- 参加済み・削除済みの人のコメントは飛ばして、同じ回のあとのコメントの処理を続ける。上限に達したときだけ打ち切る。
- 参加の条件(合言葉)は、任意で設定できる。空なら、募集中のすべてのコメントが参加になる。【案】
- コメントの受け取りは、OshikuraChain に準拠(OneSDK の購読は 1 回だけ、履歴・BOT 自身の投稿・非表示中は除く)。
- 購読に失敗したときは、募集中にせず、エラーを表示する。

### 手動での追加

- 名前を入力して追加する。**複数行を貼り付けると、1 行 1 人**として一括で追加する。【案】
- 手動で追加した人は、コメントの参加者と同じ扱い(縦線に並ぶ)。
- 追加した人は、個別に削除できる(募集中・準備中のみ)。

### 本数

- 縦線の本数は、参加者の人数と同じ。
- 上限は `PLAYER_MAX`(100)。【案】推奨は 30 本程度。超えたときは、追加できない旨を設定パネルに表示する(手動追加は、入らなかった人数も出す)。
- 参加者が 2 人未満のときは、横線の設定・発表に進めない。

## ゴール

- 縦線の下端に、ゴールを置く。ゴールの数は、縦線の数と同じ。【決定】
- **当たりだけを入力**し、残りは**自動で「はずれ」**になる。【決定】
- 当たりは**複数**入力できる。当たりの中でも、**個別の名前**(例: 「パジェロ」「たわし」)を付けられる。【決定】
- 当たりは「名前 + 個数」で入力する(例: 「たわし ×3」)。個数は省略すると 1。【案】
- 「はずれ」の表示名は、変更できる(既定は「はずれ」)。【案】
- 当たりの合計が参加者数を超えたら、警告を出し、発表に進めない。【案】
- 個数は、0 以上の整数にそろえて数える(空欄・小数・負数の入力でも、ゴールの数がずれない)。
- 参加者が増減したら、はずれの数は自動で増減する(当たりは変わらない)。
- ゴールの並び(どの縦線の下に、どのゴールが来るか)は、**ランダムに決める**(シャッフル)。【案】
- 発表の前は、ゴールを**隠す**かどうかを、切り替えられる(既定は隠す)。隠すときは、誰かが着いたゴールだけを明かす。【決定】

## 横線

### モデル

- 縦線 `n` 本、行 `R` 段の**格子**で扱う。横線は「行 `r` の、縦線 `c` と `c+1` の間」の有無で決まる。【案】
- **同じ行で、隣り合う横線は引けない**(1 本の縦線から、同じ高さで左右に横線が出ない)。この制約を守れば、必ず参加者とゴールが 1 対 1 に対応する。【決定】(あみだくじの性質)
- 行数 `R` は、縦線の本数に応じて決める(`max(12, 縦線数 × 2)` 程度)。【案】プレイして調整する。

### 引き方

| モード | 内容                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------ |
| 手動   | 盤面をクリックまたはドラッグして、横線を引く・消す。最初に押した場所に横線があれば「消す」ドラッグ、なければ「引く」ドラッグ。制約に反する場所には引けない。【決定】 |
| 自動   | 密度(`RUNG_DENSITY`、既定 0.3)を指定して、制約を守ったランダムな横線を、空きに引く。【決定】     |
| 両方   | 手動で引いた横線を残したまま、「自動で埋める」で、空きだけに足す。【決定】                       |

- 自動で引いた横線だけを消す「自動分をやり直す」ボタンを置く。手動で引いた横線は残る。【案】
- 全部消す「横線をリセット」ボタンを置く。【案】
- 横線は、発表が始まったあとは変えられない。
- 人数が減るなどで盤面の範囲外になった横線は、自動で除く。
- 盤面の移動は、準備中は Shift+ドラッグ・中ボタン・右ボタンのドラッグ、発表中は左ドラッグ。

## 発表

### 辿り方

- 縦線の上端から下へ進み、横線に当たったら、その横線で隣の縦線へ移って、また下へ進む。【決定】
- 辿った経路は、参加者ごとに色分けする。【案】
- 位置は、上端からの**高さ**(0 〜 行数)で決める。横線は、その高さを中心に少しの間で渡る。全員が同じ高さを同じ速さで進むので、全員同時でも同時に着く。【決定】

### 全員同時

- すべての参加者の線が、同時に、上から下へ辿る。
- 全体が見える表示のまま進める(拡大はしない)。【案】
- 辿り終えたら、結果の一覧を出す。

### 一人ずつ

- 参加者を**指名**して、その人の線だけを辿る。指名は、画面上の名前をクリックするか、「次の人」ボタン(順番)で行う。【案】
- 辿っている線に合わせて、自動で**拡大**(1.6 倍)して、先端が中央に来るよう追う。辿り終えたら、全体表示に戻る。【案】
- 辿り終えた人は、結果の一覧に、その人の分だけが入る。
- 全員の発表が終わったら、結果が完成する。

### 速度

- 辿る速さは、設定で変えられる。盤面を上から下まで辿りきる時間で決め、人数が多くても同じ(ゆっくり 12 秒・ふつう 6 秒・はやい 2.5 秒)。【案】
- 一人ずつは、辿っている間、別の人を選べない(「次の人へ」も押せない)。【決定】

## 表示と拡大

- 画面は、ウィンドウの大きさに合わせて縮尺が変わる(縦横比は保つ)。【案】
- 縦線が多いときの**拡大**: ボタン(＋ / －)、マウスホイール(カーソル位置が基準)、ドラッグでの移動。「全体に戻す」ボタン(倍率の表示を押す)で、全体が収まる倍率に戻す。全体が収まる倍率より小さくはならない。【決定】(拡大で対応する方針)
- 参加者名は、縦線の上端に**縦書き**で出し、7 文字を超えたら省略する(マウスを載せると全文)。ゴール名は、5 文字を超えたら省略する。【決定】
- 描画は SVG。【案】(文字の描画が簡単なため)。横線を引く・消す操作は、線ごとにイベントを持たず、盤面全体で座標から「縦線の間 × 行」を求める。100 本でも DOM が増えない。重い場合は、Canvas を検討する。

## 画面の構成

- 上部バー: 画面名・参加者数・状態(準備中 / 発表中 / 完了)・拡大操作・設定の表示切替・「次の人へ」・「結果を見る」・「もう一度」。【案】
- 設定パネル(準備中): 参加者(募集・手動追加・一覧)・ゴール(当たりリスト)・横線(モード・密度・ボタン)。【案】
- 盤面: あみだくじ本体。OBS でキャプチャする部分。【決定】
- 設定パネルは、OBS でキャプチャしたときに映らないよう、**盤面と分ける**(隠す・畳むボタンを置く)。【案】

## 結果

- 全員の発表が終わっても、結果一覧はすぐには出さない(最後の着地を配信に映すため)。上部バーの**「結果を見る」ボタン**で開く。【決定】
- 一覧は「参加者 → ゴール」で、当たりを先に並べる。「盤面に戻る」で閉じ、「もう一度」で準備に戻る。
- 結果は、画面上でのみ保持する(ログへの記録は、「未確定事項」)。

## テスト

純粋関数(`scripts/`)に、テストを書く。【案】

- 横線の制約(同じ行で隣り合う横線がない)が、自動生成でも守られる。
- どんな横線でも、辿った結果が**全単射**(全員が別々のゴールに着く)になる。
- 高さ y からの位置: 横線の数が違っても、同じ y なら同じ高さにいる。横線の途中では col が小数になる。
- 範囲外の横線の除去、不正な個数(NaN・小数・負数)の正規化、結果一覧の組み立て(ゴールが無い行は除く)。
- ゴールの補完: 当たりの合計 + はずれ = 縦線の数。当たりが多すぎるときは、エラーになる。
