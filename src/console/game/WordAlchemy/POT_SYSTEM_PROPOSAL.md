# 鍋システム仕様 追加提案

> **位置付け：追加提案**
>
> この文書は、現行の `SPEC.md`
> を直接変更せず、鍋システムの仕様変更・拡張案を整理するための提案書である。
> 現行仕様と異なる内容は、採用が決まった段階で既存仕様との整合性を確認して反映する。
>
> API実装、APIプロバイダの切り替え・予備系統などは、この提案の対象外とする。

## 1. 目的・背景

鍋ごとに名前の生成ルールを変え、材料から生まれる名前の多様性と面白さを高める。

特に重視する点は次のとおり。

- ネーミングの面白さ、語感、意外性をゲーム体験の中心に置く。
- 鍋ごとに加工方法・命名スタイル・名前の長さを変える。
- 材料の文字を厳密に使う鍋だけでなく、漢字変換や文字追加を許可する鍋も用意する。
- 闇鍋は生成AIにランダムな指示を考えさせず、ゲーム側で用意した指示プールから抽選する。
- プロンプトと出力を簡潔にし、余計な説明文を出力させない。

## 2. 基本方針

### 2.1 鍋の役割

鍋は、単なる表示名ではなく、名前の加工方法と命名スタイルを決めるルールセットとして扱う。

UI上の鍋名（例：圧力鍋、魔女の大釜）は、原則として生成AIに送信しない。AIには、鍋名そのものではなく、鍋に対応する具体的な生成指示を渡す。

### 2.2 処理順

生成処理は、次の順序とする。

1.  材料と鍋の指示をもとに名前を生成する。
2.  生成された名前をもとに分類を決める。
3.  生成された名前をもとに色を決める。

分類・色は材料から直接決めるのではなく、完成した名前・完成物の印象を基準に判断する。

### 2.3 名前の長さ

名前の最大文字数は全鍋共通にしない。鍋ごとに設定する。

- 短い名前を狙う鍋では、短さそのものをルールにする。
- フランス風など、語感や雰囲気を重視する鍋では、ある程度長い名前を許容する。
- 文字数は鍋の個性に合わせて決める。ここに記載する鍋ごとの具体的な上限値は、今後の調整対象とする。

## 3. 材料の加工ルール

鍋ごとの違いを明確にするため、材料の加工方法を次の観点で定義する。

### 3.1 文字の並べ替え・省略

材料に含まれる文字を並べ替えたり、一部を省略したりして名前を作る。

- 材料にない文字の追加は原則禁止。
- 同じ文字を材料に含まれる数より多く使わない。
- 材料の文字をどの程度残すかは、鍋ごとに指定する。

### 3.2 音・かなの変換

材料の読みや音を残しながら、表記や発音を変える。

例：

- ひらがな・カタカナの変換
- 濁音・半濁音への変換
- 音の伸縮
- 語尾や音節の調整

変換を許可する範囲は鍋ごとに指定する。

### 3.3 漢字への変換

材料の読みや意味を手掛かりに、別の漢字表記へ変換する。

- 材料の読みを保った当て字
- 材料の意味に合う漢字への置き換え
- 複数の材料の意味を組み合わせた熟語風の表現

漢字変換は、材料に含まれる文字をそのまま使うルールとは別の加工ルールとして扱う。

### 3.4 文字の追加・自由な変形

鍋によっては、材料にない文字の追加を許可する。

- 命名スタイルを成立させるための接頭語・接尾語
- 外国語風の綴りや語尾
- 型番・記号を含む表現

追加を許可する鍋でも、材料との関連性を失わないことを基本とする。追加可能な文字や表現の範囲は、鍋ごとの指示で制御する。

## 4. 鍋の候補

以下は候補案であり、採用や個別ルールは未確定とする。

---

鍋 命名スタイル 加工ルールの方向性 文字数

---

水炊き鍋 材料を素直に組み合わせた名前 文字の並べ替え・省略を中心とする 個別設定

圧力鍋 短く圧縮された名前 文字の省略・圧縮を強く促す かなり短くする

ビストロ鍋 フランス料理・洋風雑貨・高級感 音を残した変形や文字追加を許可 やや長めも許容

中華鍋 中華料理・武術の技名・四字熟語風 材料の読みや意味から漢字へ変換 個別設定

魔女の釜 呪文・魔物・魔法アイテム風 カタカナ化、濁音追加、音の変形 個別設定

ハイテク炊飯器 SF・メカ・製品名・型番風 英数字や記号を含む表現も検討 個別設定

和風土鍋 和菓子・妖怪・伝承・和風の道具風 読みや意味を活かした和風表現 個別設定

闇鍋 予測できない多様な命名スタイル 指示プールから抽選したルールを適用 個別設定

---

### 4.1 水炊き鍋

基本となる鍋。材料の文字を組み合わせ、材料とのつながりが分かる名前を作る。

- 材料の文字を並べ替え・結合・省略する。
- 原則として材料にない文字は追加しない。
- 他の鍋のような強いテーマ付けは行わない。

### 4.2 圧力鍋

短く、圧縮された名前を作る鍋。

- 材料の文字を大胆に省略・圧縮する。
- 短い名前になることを優先する。
- 文字数の上限は他の鍋より厳しくする。

### 4.3 ビストロ鍋

フランス風・洋風のおしゃれな名前を作る鍋。

- フランス料理、洋菓子、香水、雑貨、ブランド名などを連想させる。
- 材料の音や意味を残しながら、フランス語風の綴り・語尾に変形してよい。
- 命名スタイルを成立させるための文字追加を許可する。
- 他の鍋より長い名前も許容する。

### 4.4 中華鍋

材料を漢字に変換し、中華風の名前を作る鍋。

- 材料の読みや意味をもとに漢字へ変換する。
- 中華料理、武術の技名、秘伝、道具、熟語などを連想させる。
- 漢字変換を積極的に使う。
- 材料に含まれる文字の厳密な使用数にはこだわらないが、材料との意味的なつながりを保つ。

### 4.5 魔女の釜

魔法・呪文・魔物を連想させる名前を作る鍋。

- カタカナ表記を中心とする。
- 濁音・半濁音・長音などを使い、怪しさや力強さを演出する。
- 呪文、魔法薬、魔物、魔法アイテムなどの命名スタイルを使う。
- 必要に応じて文字の変形・追加を許可する。

### 4.6 ハイテク炊飯器

未来の機械や製品を連想させる名前を作る鍋。

- SF、ロボット、装置、研究施設、製品名などを連想させる。
- 型番、英数字、記号を使う形式も検討する。
- 材料の音や意味を、機械の名称・機能名へ変換する。

### 4.7 和風土鍋

日本の伝統・文化・伝承を連想させる名前を作る鍋。

- 和菓子、妖怪、妖術、伝説の道具、古風な地名などを連想させる。
- 材料の読みや意味を活かして、和風の名称に変換する。
- 必要に応じて漢字や当て字を使う。

### 4.8 将来の追加案

名前だけ。

- 蒸留器 エッセンスや純度を抽出・濃縮した鋭い名
- ビストロ鍋 フランス料理や洋菓子のような洒落た響きの名
- パエリアパン スペイン・ラテン風の陽気でリズミカルな響きの名
- タジン鍋 中東・エキゾチックで神秘的な響きの名
- スキレット アメリカン・ダイナーやアウトドア風のキャッチーな名
- サモワール ロシア・東欧風の重厚で独特な子音の響きの名
- 石焼ビビンバ鍋 韓国料理風のパンチと熱量のある響きの名
- フォンデュ鍋 スイス・アルプス風の温かみがあり可愛らしい響きの名
- ナンタンドール インド・スパイス風の芳醇で力強い響きの名
- 圧力鍋 文字を極限まで圧縮・短縮した3〜4文字の凝縮名
- スロークッカー 伸ばし棒（ー）や母音を活かしたゆったりした響きの名
- スモーカー（燻製器） 濁点・半濁点を加えて深みと渋みを出した名
- ミキサー 材料の文字を完全にバラバラに混ぜ合わせたアナグラム名
- 遠心分離機 頭文字と末尾の文字だけを抽出したシャープな名
- フラスコ 元素記号や鉱物・学術用語のような知的な響きの名
- 俳句の囲炉裏 五・七のような和のリズム感を持つ風流な名
- ネオンサイン鍋 カタカナと英語のニュアンスが混ざった都会的・ポップな名
- 祭壇（さいだん）： 神話・聖典・召喚獣・神器風の重厚な名前
- 魔法陣： 悪魔・精霊・魔導書・中二病的なカタカナ＋漢字の名前

## 5. 闇鍋の抽選方式

闇鍋は、煮込みごとに1回だけ命名指示を抽選する。

### 5.1 抽選タイミング

- 煮込み開始時、またはAIによる名前生成を開始する直前に抽選する。
- 抽選した指示は、その煮込みの間は固定する。
- AIの出力失敗などによる再試行では、同じ指示を使う。
- 再試行のたびに抽選し直してはならない。

### 5.2 指示プールの例

指示はゲーム側で事前に定義し、そこからランダムに1つ選ぶ。

---

指示の方向性 命名ルール

---

アナグラム風 材料の文字や音を大胆に並べ替え、早口言葉のような名前にする

マスコット風 材料の音を伸縮させ、かわいいペットやマスコットのような名前にする

神話・伝説風 材料の意味を大げさに解釈し、秘宝や神話上の存在のような名前にする

ダジャレ風 材料の音や意味を組み合わせ、語呂合わせを含む名前にする

高級ブランド風 香水や高級ブランドの商品名のような名前にする

料理名風 材料から想像できる、実在しそうで少し奇妙な料理名にする

必殺技風 材料をもとに、技名や攻撃名のような名前にする
------------------------------------------------------------------------------------------------------

指示プールの内容は、後から追加・削除・調整できる構成を想定する。

## 6. AIへの出力形式

出力はJSONのみとし、説明文やMarkdownを付けない。

### 6.1 入力イメージ

```text
材料:["カレーは辛","の空気清浄","せすぴん"]
指示:<鍋ごとの生成ルール>
分類:A生物 B食物 C道具 Dガラクタ（完成物で判断）
色:赤 橙 黄 緑 青 紫 白 黒 から1つ
出力JSONのみ:{"n":"名前","c":"A|B|C|D","k":"色"}
```

### 6.2 出力イメージ

```json
{ "n": "カレー清浄獣", "c": "A", "k": "紫" }
```

### 6.3 出力項目

キー 内容

---

`n` 生成した名前
`c` 分類。A:生物、B:食物、C:道具、D:ガラクタ
`k` 色。赤・橙・黄・緑・青・紫・白・黒から1つ

分類は完成物として何に見えるかを基準に判断する。色も材料そのものではなく、完成した名前・完成物の印象を基準に選ぶ。

## 7. 検証・フォールバックで考慮すること

この提案ではAPI実装そのものは扱わない。ただし、鍋によって材料の加工許可範囲が異なるため、既存の検証ルールをそのまま全鍋に適用できるとは限らない。

採用時には、少なくとも次の点を整理する必要がある。

- 材料文字の使用数を厳密に検証する鍋
- かな・音の変換を許可する鍋
- 漢字変換を許可する鍋
- 材料にない文字の追加を許可する鍋
- 文字数の上限を鍋ごとに持つ仕組み
- 闇鍋で抽選した指示を再試行時にも維持する仕組み

特に、文字の使用数を検証するルールと、名前の内容・命名スタイルを検証するルールは分けて考える。

## 8. 採用時に決める項目

以下は、この提案を採用する段階で決定する。

- 採用する鍋の種類と、初期リリースに含める鍋
- 各鍋の具体的な文字数上限
- 各鍋で許可する加工ルール
- 材料にない文字の追加を許可する範囲
- 漢字変換時に、材料との意味的なつながりをどの程度求めるか
- 闇鍋の指示プールに含める指示と、その抽選単位
- 分類・色の判定基準
- 既存の検証処理との整合性

## 9. 既存仕様との関係

この文書は追加提案であり、現行の `SPEC.md`
や実装を変更するものではない。

採用する場合は、次の順序で整理する。

1.  この提案から採用する鍋・ルールを決める。
2.  鍋ごとの加工ルールと文字数上限を確定する。
3.  既存の名前生成・検証仕様との相違点を洗い出す。
4.  合意した内容を既存仕様へ反映する。
5.  仕様に合わせて実装側の対応範囲を決める。
