# WordAlchemy(言葉の錬金術) 仕様(たたき台)

LiveConsole の `game` カテゴリのブラウザゲーム。別ウィンドウで開き、OBS でキャプチャして配信に映す。
ゲーム名・キーは `WordAlchemy` / `wordAlchemy`。OshikuraChain の派生。

## 表記

- **【決定】**: 方針として決まっていること。
- **【案】**: たたき台での提案。承認されるまで確定ではない。
- 「OshikuraChain に準拠」とあるものは、`../OshikuraChain/SPEC.md` の同名の節と同じ。定数の値は、プレイして調整する。

## 概要

- 視聴者のコメントから「ことば」(5 文字ずつ)が盤面に降ってくる。リスナーは、材料を供給する人。
- プレイヤー(配信者)は、ことばを中央の**鍋へ押し込む**。鍋に材料が 3 つ入ると煮込みが始まる。
- 生成 AI が、材料から**名前・分類・色**を決める。ゲーム側が、分類と色に合うアイテムを抽選する。
- できたものは図鑑に登録される。**目的は収集**(100 種の図鑑を埋める)。
- 生成 AI の利用料金は、プレイヤー(配信者)の負担。ゲーム側は共通の API キーを持たない。【決定】

## 遊びの流れ

1. コメントから、ことばが盤面に降ってくる。
2. 主人公(WASD)が、ことばを押して、鍋に押し込む。
3. 材料が 3 つ入ると、煮込みが始まる(材料は消費される)。
4. 生成 AI が `{c, k, n}`(分類・色・名前)を返す。ゲーム側が検証する。
5. ゲーム側が、分類と色に合うアイテムを抽選する。
6. 鍋から、アイテムと名前が出てくる。図鑑に登録する。

## 盤面

- 横 12 列 × 縦 8 行(`GRID_COLS` / `GRID_ROWS`)、1 マス 64px(`CELL_PX`)。【決定】
- 盤面は 768 × 512px。上部バー(40px)を足して、`windowSize` は 768 × 552。`ConsoleViewMap.ts` の `windowSize` も合わせる。
- 中央に **2 × 2 マスの鍋**を置く(列 6〜7・行 4〜5。1 始まり)。12 も 8 も偶数なので、ちょうど中央になる。【決定】
- 鍋は障害物扱い。主人公は入れない。
- 画面はウィンドウの大きさに合わせて縮尺が変わる(縦横比は保つ)。移動と当たり判定は、すべてマス単位。

## 主人公の操作

OshikuraChain に準拠(WASD、1 マスずつ移動、押し出し、連鎖して一緒に押す、ウェーブの遅延)。

- 得点のクールダウン(`HERO_PUSH_INTERVAL_SECONDS`)は、このゲームには無い。【案】
- 障害物や壁で動けないときは、動いたことにならない。

## ことば

- コメントの文字を `WORD_CHARS_PER_ITEM`(5)文字ずつに分けた「ことば」が、空いているマスにランダムに降る。1 コメントあたり最大 `WORD_MAX_PER_COMMENT` 個。空白だけ・本文なしなら降らない。
- 1 マスの白い札。同時数上限 `WORD_MAX`(超えたら古いものから消す)。
- **盤面の外へ押し出されたことばは、消える**(得点ではない。袋小路を作らないため)。【決定】
- 「wwwww」・数字だけ・記号だけのことばも、除外せずに降らせる。扱いは鍋の性格で決める(後述)。【決定】
- OshikuraChain の**爆発・倍率・残り時間・連鎖・巨大化・ギフト効果は持ち込まない**。ことばは時間で壊れない。【案】
- アイコンは出さない。【案】

## 鍋

### 鍋の種類

- 命名スタイルは、ランダム抽選せず、**鍋の種類として予め決める**。【決定】
- 鍋の種類はコンフィグで選ぶ(1 ゲーム 1 鍋)。保存する設定は `potType`。【案】
- 鍋ごとに、次の 3 つを持つ。
  - **許可する変換**(文字をどう変えてよいか)。
  - **性格**(どのことばを受け付けるか)。
  - **AI への指示文**(固定)。
- 見た目は、鍋ごとに変える(スプライトの差し替え、または色替え)。【案】

### 許可する変換

「材料にない文字を追加してはいけない」という規約は守る。【決定】
鍋が許可する変換は、**同じ文字の形の変化**に限る。【案】

| 変換           | 内容                                 |
| -------------- | ------------------------------------ |
| 並べ替え・結合 | 全鍋で許可                           |
| 省略           | 材料の文字を使わなくてよい(鍋による) |
| かな変換       | ひらがな ↔ カタカナ                  |
| 清濁変換       | 清音 ↔ 濁音・半濁音(か ↔ が など)    |

### 鍋の種類(案)

| 鍋       | 許可する変換                 | 性格                       |
| -------- | ---------------------------- | -------------------------- |
| 水炊き鍋 | 並べ替え・結合のみ(全部使う) | 数字だけ・記号だけは投げる |
| 圧力鍋   | 並べ替え・結合・省略(短く)   | 数字だけ・記号だけは投げる |
| 闇鍋     | 清濁変換                     | 何でも受け付ける           |
| カナ鍋   | かな変換                     | 記号だけは投げる           |

鍋の数と内容は未確定(【案】)。

### 鍋の性格(受け付けと投げ飛ばし)

- 鍋は、ことばを受け付けるかどうかを、ゲーム側の決定的な関数 `accepts(word)` で決める(AI は関係しない)。【案】
- 判定の例: 数字だけ、記号だけ、絵文字だけ、「w」だけ。
- 受け付けないことばは、**鍋が投げ飛ばす**。飛ばし先は空いているマス。空きがなければ消える。【案】
- **煮込み中(AI の返事待ちを含む)も、鍋はことばを受け付けず、投げ飛ばす**。【案】

## 錬金術のルール

- 材料は 3 つ。鍋に投入すると消費される。【決定】
- 材料の一部を名前に残さなくてもよい(鍋による)。【決定】
- 材料にない文字・単語を追加してはいけない。ただし、鍋が許可する変換は除く。【決定】
- 材料の文字を並べ替えたり、結合したりして名前を作る。【決定】
- 同じ材料でも、毎回同じ名前になる必要はない。名前の重複チェックは行わない。【決定】
- 名前の長さには上限を置く(例: 12 文字)。【案】

## 生成 AI の出力と検証

### 出力

生成 AI には、**分類・色・名前だけ**を決めさせる。実際に表示するアイテムは、ゲーム側が抽選する。
アイテムの一覧(100 種)を AI に渡す必要はない。

```json
{ "c": "A|B|C|D", "k": "色", "n": "名前" }
```

- `c`: 分類(A 生物 / B 食物 / C 道具 / D ガラクタ。完成物の性質で判断)。【決定】
- `k`: 色。固定のパレットから 1 つ選ばせる。パレット: 赤・橙・黄・緑・青・紫・白・黒 の8種。
- `n`: 生成物の名前。

### プロンプト(案)

指示文は、鍋ごとに固定。材料は、**JSON 配列**で渡す(コメントに含まれるカンマや引用符で壊れないように)。
ユーザー名・ID は送らない。ことばだけを送る。

```
材料: ["カレーは辛","の空気清浄","せすぴん"]
鍋: <鍋の指示文。例: 圧力鍋。材料の文字を並べ替え・結合し、一部を省略して短い名前を作れ>

材料と鍋にない文字・単語の追加は禁止。
分類: A生物 B食物 C道具 Dガラクタ(完成物の性質で判断)。
色: 赤橙黄緑青紫白黒 から 1 つ。
出力は {"c":"A|B|C|D","k":"色","n":"名前"} のみのJSON。
```

### 検証(ゲーム側)【案】

1. JSON として読める(コードフェンスは取り除く)。
2. `c` が A〜D、`k` がパレット内。パレット外の `k` は、ランダムで置き換える。
3. 名前が、NFC に正規化したうえで、鍋が許可する変換の同値クラスを使い、**材料の文字の範囲に収まっている**。「・」などの記号は、許可リストで扱う。
4. 名前が空でなく、長さの上限以内。
5. 検証に失敗したら、最大 2 回までやり直す。それでも失敗したら、Mock にフォールバックする。

「重複時の再生成はしない」とは別の話。やり直すのは、検証に失敗したときだけ。

### Mock(規則ベース)

AI を使えないとき(キー未設定・エラー・無料枠の使い切り)の代替。鍋の変換規則を使って、材料の文字を並べ替え・省略し、分類と色はランダムにする。
ゲーム全体を、キーなしで通して遊べる。テストにも使う。【案】

## AI への接続

- 利用者が、自分で API キーを設定する。ゲーム側に共通キーは持たせない。【決定】
- 対応するのは、**OpenAI 互換**(baseURL・モデル・キーを指定)と Anthropic。OpenAI 互換なので、Groq などの無料枠のあるサービスや、Ollama・LM Studio のようなローカル LLM も使える。【案】
- 呼び出しは、**サーバー側の中継ハンドラ**を通す(ブラウザからの CORS を避ける。ローカル LLM も `localhost` を直接呼べる)。【案】
- キーの入力欄は伏せ字にする(コンソール画面は OBS に映る)。配布物・ログにキーを載せない。【案】
- AI の呼び出しは非同期で、rAF のループの外に置く。結果は、外からエンジンに渡す(純粋関数のエンジンは維持する)。【案】

### 回数・料金の制限【案】

- 呼び出しが起きるのは、鍋に 3 つ入れたときだけ。コメント数や視聴者数では増えない。
- 煮込みの最短時間を置く(演出込みで 5 秒など)。サービスごとの上限に合わせて変えられる設定にする。
- 1 ゲームの回数上限を置く(既定は安全側。値は未定)。画面に、今回の使用回数を出す。
- `max_tokens` を小さく絞る。入力は、材料と鍋の指示文だけ。
- 429(上限超過)が返ったら、Mock にフォールバックして、その旨を表示する。
- 無料枠の上限は、サービスが予告なく変えることがある。数値は、仕様書に固定せず、設定とする。

## 分類とアイテム

- 分類は A 生物・B 食物・C 道具・D ガラクタ。**各 25 種、計 100 種**。【決定】
- アイテムはドット絵。画像は静止画で、動きはコードで付ける(ふわふわ上下、ポンと拡大など。全アイテム共通)。【案】
- 抽選: 分類で絞る → 色で絞る → 該当がなければ分類だけで抽選する。抽選は `drawByWeight`(重み付き)を使う。【案】
- アイテムの一覧はデータ駆動(`id` / 分類 / 色 / 画像 / 重み)にして、素材を差し替えやすくする。【案】
- 色は、ビルド時のスクリプトで、画像の支配色から自動で付ける(輪郭は除く。外れたものは手で直す)。【案】
- 最初は各分類 10 種(計 40 種)でも動くようにして、100 種へ増やしながら進める。【案】

## 図鑑

- 図鑑は、レシピ集ではなく、新種を発見して収集する仕組み。【決定】
- **図鑑のキーは、名前ではなく、100 種のアイテム**。名前は付属情報にする(最初の名前と、直近の数個、素材を出した視聴者名、鍋の種類、日時)。【案】
- 画面に「発見 n/100」を常時表示。未発見はシルエット。既発見のアイテムがまた出たときは「既発見」と出して、名前だけを履歴に足す。【案】
- 保存: `game-configs` と同じ仕組みで、別の `gameKey`(例: `wordAlchemyCodex`)に保存する。`GameConfigKeySchema` のキー形式の制約は未確認。【案】
- リセット: 「やめる」と同じ 2 回押し。【案】
- 保存期間・リセットの仕様は、未決定。

## 時間の進め方

OshikuraChain に準拠(ウィンドウが非表示の間はゲームも止まる、ゲーム内の時計、固定刻み、rAF だけで更新)。

- 煮込み中は、鍋が「煮込み中」の状態になる。AI の結果(または Mock の結果)が届いたら、アイテムを出す。
- ウィンドウが非表示の間は、煮込みの演出も止まる。AI の返事は、届いたものを保持する。【案】

## コメントの受け取り

OshikuraChain に準拠(OneSDK の購読は 1 回だけ、履歴・リセット・BOT 自身の投稿・ゲーム中以外・非表示中は除く、`meta.isExternal` は区別しない)。

- テストコメント、コメントオートモードは流用する予定。【案】
- ことばの出現時と、完成した名前に、NG ワードのフィルターをかける(既存の機構があれば流用)。【案】
- 初見(`meta.tc === 1`)の特別扱いは、このゲームには無い。【案】

## 画面

- 上部バー: ゲーム名・鍋の種類・発見 n/100・AI の状態(使用回数)・やめるボタン。【案】
- 盤面(Excalibur): 床と壁(錬金術の工房らしい背景)、鍋、主人公、ことば(白い札)。【案】
- 演出(出現): 上から落下(OshikuraChain と同じ)。
- 演出(投入): ことばが鍋に吸い込まれる。
- 演出(煮込み): 泡・湯気などのパーティクル(コードで描く)。
- 演出(完成): アイテムと名前を出す。新種のときは派手に、既発見のときは控えめに。
- 演出(投げ飛ばし): 鍋が受け付けないことばを弾く。
- テストコメント(左下): `H` キーで隠す / 戻す。

## 素材

- フィールドの素材は **Kenney** を使う。【決定】Tiny Dungeon・Tiny Town・Tiny Creatures(作者は別。いずれも CC0)などを候補とする。
- 16 × 16 の素材を 4 倍にして、`CELL_PX`(64)に合わせる。表示は最近傍補間(`image-rendering: pixelated`)。
- 100 種のアイテムは、まず Tiny 系だけで数えて、足りない分類(食物など)を他のパックで補う。【案】
- 要確認: 鍋・薬瓶・棚などの錬金術らしい小物があるか。なければ、壺や樽を色替えするか、自作する。
- 出典・ライセンス・取得日は `CREDITS` に残す(クレジット表記が必須でなくても残す)。
- 画像は `images/WordAlchemy/`(`field/` `pot/` `items/` `effects/`)にまとめる。素材がなければ、その画像が出ないだけでゲームは動く。

## 記録(GameLog)

【案】

- 図鑑の発見ごとに、素材を出したユーザーへ貢献を記録する(`eventKey` は未定)。
- ユーザーの得点(`update-user-stats`)は変えない。
