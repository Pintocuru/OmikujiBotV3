# WordAlchemy(言葉の錬金術) 仕様(たたき台)

LiveConsole の `game` カテゴリのブラウザゲーム。別ウィンドウで開き、OBS でキャプチャして配信に映す。
ゲーム名・キーは `WordAlchemy` / `wordAlchemy`。OshikuraChain の派生。

## 表記

- **【決定】**: 方針として決まっていること。
- **【案】**: たたき台での提案。承認されるまで確定ではない。
- 鍋の仕様は、追加提案 `POT_SYSTEM_PROPOSAL.md` の 8 鍋を採用して【決定】した(提案書は経緯として残す。現行の 4 鍋は仮のものだった)。提案の採用で変わった旧【決定】は、「(旧: …)」と残す。
- 「OshikuraChain に準拠」とあるものは、`../OshikuraChain/SPEC.md` の同名の節と同じ。定数の値は、プレイして調整する。

## 概要

- 視聴者のコメントから「ことば」(5 文字ずつ)が盤面に降ってくる。リスナーは、材料を供給する人。
- プレイヤー(配信者)は、ことばを中央の**鍋へ押し込む**。鍋に材料が 3 つ入ると「この内容で煮込みますか?」と確認が出て、「煮込む」を選ぶと煮込みが始まる。
- 生成 AI が、材料から**名前**を作り、その名前から**分類・色**を決める(この順)。ゲーム側が、分類と色に合うアイテムを抽選する。【決定】
- できたものは図鑑に登録される。**目的はアイテムの収集**。初期アイテムは 32 種とし、将来的な追加にも対応する。
- 生成 AI の利用料金は、プレイヤー(配信者)の負担。ゲーム側は共通の API キーを持たない。【決定】

## 遊びの流れ

1. コメントから、ことばが盤面に降ってくる。
2. 主人公(WASD)が、ことばを押して、鍋に押し込む。
3. 材料が 3 つ入ると、「この内容で煮込みますか?」の確認が出る(「煮込む」を選ぶと、材料は消費されて煮込みが始まる)。
4. 生成 AI が `{n, c, k}`(名前・分類・色)を返す。ゲーム側が検証する。
5. ゲーム側が、分類と色に合うアイテムを抽選する。
6. 鍋から、アイテムと名前が出てくる。図鑑に登録する。

## 盤面

- 横 12 列 × 縦 8 行(`GRID_COLS` / `GRID_ROWS`)、1 マス 64px(`CELL_PX`)。【決定】
- 盤面は 768 × 512px。上部バー(40px)を足して、`windowSize` は 768 × 552。`ConsoleViewMap.ts` の `windowSize` も合わせる。
- 中央に **2 × 2 マスの鍋**を置く(列 6〜7・行 4〜5。1 始まり)。12 も 8 も偶数なので、ちょうど中央になる。【決定】
- 鍋は障害物扱い。主人公は入れない。鍋が閉じているとき(確認待ち・煮込み中・材料が揃う予定のとき)は、ことばを鍋へ押しても動かない(「鍋」の節)。【決定】
- 外周の 1 マス(縁)は、主人公の通り道。ことばは縁に置かない(「ことば」の節を参照)。【決定】
- 画面はウィンドウの大きさに合わせて縮尺が変わる(縦横比は保つ)。移動と当たり判定は、すべてマス単位。

## 主人公の操作

OshikuraChain に準拠(WASD、1 マスずつ移動、押し出し、連鎖して一緒に押す、ウェーブの遅延)。

- 得点のクールダウン(`HERO_PUSH_INTERVAL_SECONDS`)は、このゲームには無い。【案】
- 障害物や壁で動けないときは、動いたことにならない。

## ことば

- コメントの文字を `WORD_CHARS_PER_ITEM`(5)文字ずつに分けた「ことば」が、空いているマスにランダムに降る。1 コメントあたり最大 `WORD_MAX_PER_COMMENT` 個。空白だけ・本文なしなら降らない。
- 1 マスの白い札。同時数上限 `WORD_MAX`(超えたら古いものから消す)。
- **ことばは、外周の 1 マス(縁)には置かない**。降る位置と、鍋が投げ飛ばす着地先は、縁を除いた内側のマスにする。【決定】
- **ことばが縁のマスへ押し込まれたら、消える**(得点ではない)。縁に入ったことばは、縁に沿ってしか動かせず、鍋に入れられなくなる(袋小路になる)ため。主人公は縁を歩けるので、縁から内側へ押せば、どのことばも鍋の方向へ動かせる。【決定】
- 「wwwww」・数字だけ・記号だけのことばも、除外せずに降らせる。どの鍋も、何でも受け付ける。【決定】
- OshikuraChain の**爆発・倍率・残り時間・連鎖・巨大化・ギフト効果は持ち込まない**。ことばは時間で壊れない。【案】
- アイコンは出さない。【案】

## 鍋

### 鍋の役割

- 鍋は表示名ではなく、**名前の命名スタイルと加工方法を決める指示文のルールセット**。【決定】
- 鍋の表示名(圧力鍋など)は、AI に送らない。AI には、鍋に対応する**短い指示文**だけを渡す。【決定】
- 命名スタイルは、ランダム抽選せず、**鍋の種類として予め決める**。【決定】(闇鍋だけは、煮込みごとに、ほかの鍋から引く)
- 鍋の種類はタイトル画面で選ぶ(1 ゲーム 1 鍋)。保存する設定は `potType`。【決定】(コンフィグは未実装)
- 鍋は、`maps/WordAlchemyPotMap.ts` に定義する。鍋が増えたら、ここに足す(闇鍋の候補にも自動で入る)。【決定】
- 見た目は、鍋ごとに**同じ絵の色替え**で変える(`PotLook` の `body` / `liquid`。煮込み中は、どの鍋も緑に泡立つ)。闇鍋は、正体を伏せるため、色を変えず暗い色に固定する。【決定】

### 鍋の種類【決定】

どの鍋も、材料の文字の並べ替え・結合・省略ができる。指示文は短く書く(トークンの節約)。
次の表の「指示の方向」を、実際の指示文にしている(文面は `WordAlchemyPotMap.ts`)。

| 鍋             | 指示の方向                                                                         |
| -------------- | ---------------------------------------------------------------------------------- |
| 水炊き鍋       | 並べ替え・結合・省略で、材料とのつながりが分かる素直な名前                         |
| 圧力鍋         | 大胆に省略・圧縮した、6 文字以内の短く凝縮した名前                                 |
| ビストロ鍋     | フランス料理・洋菓子・香水・雑貨風。フランス語風の綴り・語尾、文字の追加も可       |
| 中華鍋         | 材料の読みや意味を漢字に変換。中華料理・武術の技名・四字熟語風                     |
| 魔女の釜       | 呪文・魔法薬・魔物・魔法アイテム風。カタカナ中心、濁音・長音、文字の変形・追加も可 |
| ハイテク炊飯器 | SF・ロボット・装置・製品名風。機能名への変換、型番・英数字・記号も可               |
| 和風土鍋       | 和菓子・妖怪・妖術・伝説の道具風。漢字・当て字も可                                 |
| 闇鍋           | 煮込みごとに、闇鍋自身を除く全ての鍋から 1 つ引いた鍋の指示                        |

- 名前が長いときは、結果のカードの中で折り返す。【決定】
- 材料にない文字の追加は、検証では見ない(「検証」の節)。追加してよい範囲は、各鍋の指示文で伝える。【決定】
- 数値(圧力鍋の 6 文字など)は、プレイして調整する。

### 闇鍋の抽選【決定】

- 闇鍋は、闇鍋自身を除く**全ての鍋から**、煮込みごとに **1 回だけ**ランダムに引き、その鍋の指示文を使う。指示プールは別に作らない。
- 引くタイミングは、煮込みの開始時(AI への問い合わせの前)。引いた鍋は、その煮込みの間は固定する。検証失敗などの再試行でも、同じ鍋の指示を使う(抽選し直さない)。
- どの鍋を引いたかは、煮込み中は伏せる。完成のカードで、名前と一緒に明かす(例: 「新種発見！ (中華鍋だった)」)。図鑑・ゲームログの鍋の種類は、選んだ鍋(闇鍋)のまま。
- Mock も、引いた鍋で動く(Mock の鍋の違いは、圧力鍋だけ短くすること)。

### 煮込みの確認【決定】

- 材料が 3 つ入ったら、**「この内容で煮込みますか?」**を出す(どの鍋でも、同じ文言。ハイテク炊飯器も同じ)。何を煮込むのかを見せることと、API の節約が目的。
- 確認には、3 つの材料(ことば)を表示する。盤面の下に、確認のパネルを出す。
- 答え方は、パネルのボタンをクリック、または、キー(Enter で「煮込む」/ Esc で「やめる」)。両方使える。
- 「煮込む」: 材料は消費されて、煮込みが始まる(AI への問い合わせは、ここで初めて行う)。
- 「やめる」: **3 つの材料は消える**(消費される)。AI には聞かない。
- 確認待ちの間も、盤面は止めない(ことばは降り続け、主人公も動ける。鍋だけが答え待ち)。ウィンドウが非表示の間は、これまでどおりゲームが止まる。
- 確認には、時間切れ(自動で煮込む・やめる)を設けない。
- ゲームをやめた(やめるボタン)とき、確認待ちの材料は消える。

### 鍋が閉じているとき【決定】

- 鍋は、ことばを**何でも受け付ける**(数字だけ・記号だけ・絵文字だけも)。受け付けないことばを投げ飛ばす仕組みは、なくした。(旧: 鍋ごとに数字だけ・記号だけを投げる【案】)
- **確認待ち・煮込み中(AI の返事待ちを含む)・材料が揃う予定のとき**は、鍋が閉じている。ことばを鍋へ押しても動かない(鍋は障害物のまま、ことばは盤面に残る)。

## 錬金術のルール

- 材料は 3 つ。確認で「煮込む」を選ぶと消費される。【決定】
- 材料の一部を名前に残さなくてもよい(全鍋で許可)。【決定】
- 材料の文字を並べ替えたり、結合したりして名前を作るのが基本。鍋によっては、文字の変形・追加・漢字への変換もする(各鍋の指示文)。【決定】
- 名前の文字と長さは、ゲーム側で検証しない。錬金術は不安定なので、材料にない文字が出ても、名前が長くなってもよい、という扱い。【決定】(旧: 材料にない文字の追加は禁止・文字の使用数を検証・全鍋で最大 12 文字)
- 同じ材料でも、毎回同じ名前になる必要はない。名前の重複チェックは行わない。【決定】

## 生成 AI の出力と検証

### 出力

生成 AI には、**名前・分類・色だけ**を決めさせる。実際に表示するアイテムは、ゲーム側が抽選する。
処理の順序は、鍋の指示と材料から**名前を作る → 名前から分類を決める → 名前から色を決める**。【決定】
アイテムの一覧を AI に渡す必要はない。

```json
{ "n": "名前", "c": "A|B|C|D", "k": "色" }
```

- `n`: 生成物の名前。
- `c`: 分類(A 生物 / B 食物 / C 道具 / D ガラクタ。完成物の性質で判断)。【決定】
- `k`: 色。固定のパレットから 1 つ選ばせる。パレット: 赤・橙・黄・緑・青・紫・白・黒 の8種。材料そのものではなく、完成した名前・完成物の印象で選ぶ。【決定】
- 出力は JSON のみ。説明文や Markdown を付けない。キーの順は `n` → `c` → `k`(名前を先に決めさせる)。【決定】

### プロンプト【決定】

指示文は、鍋ごとに固定(闇鍋は、引いた鍋の指示文)。材料は、**JSON 配列**で渡す(コメントに含まれるカンマや引用符で壊れないように)。
ユーザー名・ID・鍋の表示名は送らない。ことばと指示だけを送る。プロンプトと出力は簡潔にする。名前の長さの共通の行や、文字の追加を禁止する行は、持たない(必要なら、鍋の指示文に含める)。

```
材料:["カレーは辛","の空気清浄","せすぴん"]
指示:<鍋ごとの指示文。例: 材料を大胆に省略・圧縮して、6文字以内の短く凝縮した名前にする>
分類:A生物 B食物 C道具 Dガラクタ(完成物で判断)
色:赤 橙 黄 緑 青 紫 白 黒 から1つ
出力JSONのみ:{"n":"名前","c":"A|B|C|D","k":"色"}
```

### 検証(ゲーム側)【決定】

1. JSON として読める(コードフェンスは取り除く)。
2. `c` が A〜D、`n` が空でない文字列。
3. `k` がパレット内。パレット外の `k` は、失敗にせず、ランダムで置き換える。
4. 検証に失敗したら、初回を含め最大 3 回(再試行 2 回)まで試す。それでも失敗した場合は Mock にフォールバックする。闇鍋の再試行は、引いた鍋の指示を維持する。

名前の文字(材料の範囲に収まっているか)・長さ(圧力鍋の 6 文字を含む)・命名スタイルは、検証しない。
「重複時の再生成はしない」とは別の話。やり直すのは、検証に失敗したときだけ。

### Mock(規則ベース)【決定】

AI を使えないとき(キー未設定・エラー・無料枠の使い切り)の代替。全鍋で同じ処理: 材料の文字を並べ替え・省略して名前を作り、分類と色はランダムにする。圧力鍋だけ、材料の半分ほど(最大 6 文字)に短くする。
鍋ごとの変換(漢字・カタカナ化・文字追加など)は、規則ベースでは再現できないので、行わない。
ゲーム全体を、キーなしで通して遊べる。テストにも使う。

## AI への接続

- 利用者が、自分で API キーを設定する。ゲーム側に共通キーは持たせない。【決定】
- 対応するのは、**OpenAI 互換 API**(baseURL・モデル・キーを指定)と Anthropic。【決定】OpenAI 互換 API を通じて、互換サービスやローカル LLM も利用できる。
- 呼び出しは、**サーバー側の中継ハンドラ**を通す(ブラウザからの CORS を避ける。ローカル LLM も `localhost` を直接呼べる)。【決定】
- 接続先は **「メイン」と「サブ」の 2 つ**。無料枠ではすぐ上限に達したり、通信エラーになったりするため、サブで補う。メインが上限超過(429)・通信エラー・認証エラーのときは、サブに切り替える。【決定】
- 上限超過した接続先は、`Retry-After` の間(なければ 60 秒。最大 10 分)は使わず、その間はサブだけを使う。休みが明けたら、メインを試し直す。それ以外の失敗は 15 秒、認証エラーは 60 秒休ませる。休ませる時間は【案】。
- どちらも使えない・未設定のときは、Mock で続ける。上限超過で Mock になったときは、上部バーに表示する。【決定】
- キーは `server/ai-settings.json` に保存する(`.gitignore` 済み)。画面には返さず、末尾 4 文字のヒントだけ返す。保存するときにキーを空にすると、保存済みのキーを使う。【決定】
- API は `load-ai-settings`(GET)・`save-ai-settings`(POST)・`ask-ai`(POST)。`ask-ai` のエラーは、400 = 未設定 / 429 = 使える接続先がすべて上限超過 / 502 = すべて失敗。【決定】
- キーの入力欄は伏せ字にする(コンソール画面は OBS に映る)。配布物・ログにキーを載せない。【決定】
- AI の呼び出しは非同期で、rAF のループの外に置く。結果は、外からエンジンに渡す(進行の純粋関数エンジンは作らず、結果は `brew` の返り値で盤面に渡す)。【決定】

### 回数・料金の制限

- ユーザー単位の回数制限は設けず、ゲーム全体の同時処理数とリクエスト間隔で制御する。【決定】

- 呼び出しが起きるのは、鍋に 3 つ入れたときだけ。コメント数や視聴者数では増えない。
- 煮込みの最短時間を置く(演出込みで 5 秒など)。サービスごとの上限に合わせて変えられる設定にする。
- 1 ゲームの回数上限や画面上の使用回数表示は、AI 担当エージェントと検討する。【保留】
- `max_tokens` を小さく絞る。入力は、材料と鍋の指示文だけ。
- 429(上限超過)が返ったら、サブが設定されていればサブに切り替え、使える接続先がなければ Mock にフォールバックして、その旨を表示する。
- 無料枠の上限は、サービスが予告なく変えることがある。数値は、仕様書に固定せず、設定とする。

## 分類とアイテム

- 分類は A 生物・B 食物・C 道具・D ガラクタ。初期アイテムは **4 分類 × 8 色の各組み合わせに 1 種ずつ、計 32 種**とする。【決定】
- 将来的に同じ分類・色の組み合わせへ複数のアイテムを追加できる。
- アイテムは個別のドット絵を用意する。画像は静止画とし、出現・消滅には全アイテム共通のモーションを使う。【決定】
- 抽選: AI が判定した分類と色の両方に一致するアイテムから選ぶ。初期状態では各組み合わせ 1 種のため抽選は発生しない。【決定】
- 同じ分類・色に複数のアイテムがある場合は、レアリティの重みによる抽選を行う。【決定】重みはコモン 4、アンコモン 3、レア 2 とする。
- 初期 32 種はすべてコモンとする。アンコモン・レアは、同じ分類・色の組み合わせにアイテムを追加した場合に使用する。【決定】
- 分類は A〜D の 4 種、色は赤・橙・黄・緑・青・紫・白・黒の 8 種で固定し、今後増やさない。【決定】追加アイテムは既存の分類・色の組み合わせに追加する。
- 分類・色の両方に一致するアイテムが存在しない場合は、抽選エラーとして扱う。アイテムは生成せず、「魔法のように消えてしまった！」など、複数用意したメッセージからランダムに 1 つ表示する。【決定】
- アイテムの一覧はデータ駆動(`id` / 分類 / 色 / レアリティ / 画像)にして、素材を差し替えやすくする。【案】
- 色は、ビルド時のスクリプトで、画像の支配色から自動で付ける(輪郭は除く。外れたものは手で直す)。【案】

## 図鑑

- 図鑑は、レシピ集ではなく、新種を発見して収集する仕組み。【決定】
- **図鑑のキーは名前ではなく、変更されない固有アイテム ID**とする。名前変更や表示名の重複で別アイテムとして扱わない。【決定】
- 同じアイテムを複数回発見しても、図鑑本体には 1 件だけ登録する。発見のたびに発見履歴は追加する。【決定】
- 名前は付属情報として、初回の名前と直近 5 件の名前履歴を保存する。発見履歴にはアイテム ID・発見日時・材料を出した視聴者名・鍋の種類など、必要最小限の情報を記録する。アイテム定義や画像データを履歴ごとに複製しない。【決定】
- 発見履歴は再発見も含めて保存する。履歴件数の上限は設けない。【決定】
- 画面に「発見 n/登録アイテム数」を常時表示する。分母は登録されているアイテム数に連動させる。未発見アイテムは Lucide の「？」アイコンで表示する。カテゴリ順に並べ、カテゴリ内の色順は実装エージェントに一任する。【決定】
- 既発見のアイテムがまた出たときは「既発見」と出して、名前履歴と発見履歴を更新する。【決定】
- 保存: 配信者ごとに永続保存する。保存先は `game-configs` と同じ仕組みを使い、別の `gameKey` に保存する。キーは `wordAlchemyCodex`(`GameConfigKeySchema` のキー形式に合うことを確認済み)。【決定】
- 保存データにはデータバージョンを持たせる。バージョン不一致や読み込み時の破損などで正常に読み込めない場合は、既存データを破棄して初期化する。旧データからのマイグレーションは行わない。【決定】
- アイテム追加・変更によるデータ互換性は保証しない。データバージョンが異なる場合は既存データを破棄してよい。【決定】
- リセット: 確認ダイアログを表示し、発見履歴を含む当該配信者の図鑑データをすべて削除する。削除用の API はないため、初期状態での上書き保存で行う。【決定】

## 時間の進め方

OshikuraChain に準拠(ウィンドウが非表示の間はゲームも止まる、ゲーム内の時計、固定刻み、rAF だけで更新)。

- 確認で「煮込む」を選ぶと、鍋が「煮込み中」の状態になる。AI の結果(または Mock の結果)が届いたら、アイテムを出す。
- ウィンドウが非表示の間は、煮込みの演出も止まる。AI の返事は、届いたものを保持する。【案】

## コメントの受け取り

OshikuraChain に準拠(OneSDK の購読は 1 回だけ、履歴・リセット・BOT 自身の投稿・ゲーム中以外・非表示中は除く、`meta.isExternal` は区別しない)。

- テストコメント、コメントオートモードは流用する予定。【案】
- NG ワード機能は設けない。コメント由来のことばを NG ワードで除外せず、ガラクタになることもゲーム性として扱う。【決定】
- 初見ユーザーへのボーナス・特別扱いは一切設けない。全ユーザーを同じ条件で扱う。【決定】

## 画面

- 上部バー: ゲーム名・鍋の種類・発見 n/登録アイテム数・AI の状態(使用回数)・やめるボタン。【案】
- 盤面(Excalibur): 床と壁(錬金術の工房らしい背景)、鍋、主人公、ことば(白い札)。部屋は鍋ごとに変えず、**固定の工房**にする。【決定】
  - 床: 木の板張り。素材に継ぎ目のない床のタイルがないため、コードで描く(`render/draw.ts`)。
  - 壁(外周 1 マス): 素材のキッチンカウンターと棚のタイル(瓶が並ぶものを多めに)。上の壁は瓶の並ぶ棚、下・左右は、カウンターの前面。盤面の背景として、少し暗くする(`render/boardTiles.ts`)。
  - 素材を読み込めなければ、仮の見た目(暗い茶色の面)のまま動く。
- 演出(出現): 上から落下(OshikuraChain と同じ)。
- 演出(投入): ことばが鍋に吸い込まれる。
- 演出(煮込み): 泡・湯気などのパーティクル(コードで描く)。
- 演出(完成): アイテムと名前を出す。新種のときは派手に、既発見のときは控えめに。名前が長いときは折り返す。闇鍋は、引いた鍋を明かす。
- 煮込みの確認: 材料が揃ったら、盤面の下にパネルを出す(3 つの材料、「煮込む」「やめる」のボタン)。盤面は止まらない。
- 演出(やめる): 「煮込まない」を選んだとき、鍋が材料を弾く(材料は消える)。
- テストコメント(左下): `H` キーで隠す / 戻す。

## 素材

- フィールドの素材は **Kenney** を使う。【決定】Tiny Dungeon・Tiny Town・Tiny Creatures(作者は別。いずれも CC0)などを候補とする。
- 16 × 16 の素材を 4 倍にして、`CELL_PX`(64)に合わせる。表示は最近傍補間(`image-rendering: pixelated`)。
- 初期 32 種のアイテムは、まず Tiny 系だけで数えて、足りない分類(食物など)を他のパックで補う。【案】
- 既存の Kenney 素材を優先し、不足する素材のみ新規作成する。【決定】
- `assets/images/2026-Q4/WordAlchemy/roguelikeIndoor_transparent.png`(Roguelike Indoors。16px、間隔 1px)を、盤面の壁に使う。【決定】(旧: フィールド用マップ素材の候補として確認する)
  - 素材は家具が中心で、床のタイルはない。床はコードで描き、壁にカウンター・棚のタイルを使う。
  - 盤面は WebGL の絵として使うので、画像を別のオリジンから読むとき(開発時の `VITE_IMAGE_BASE_URL`)は、CORS で読める必要がある。読めなければ、仮の見た目のまま動く。
- 出典・ライセンス・取得日は `CREDITS` に残す(クレジット表記が必須でなくても残す)。
- 画像は `images/WordAlchemy/`(`field/` `pot/` `items/` `effects/`)にまとめる。素材がなければ、その画像が出ないだけでゲームは動く。

## 記録(GameLog)

- 図鑑の発見ごとに、素材を出したユーザーへの貢献を記録する。既存の `append-game-logs` で足りるため、新しい API は作らない。【決定】
- `eventKey` は `wordAlchemy`。材料を出したユーザーごとに 1 件(同じユーザーが複数の材料を出しても 1 件)。`id` は「煮込みごとの ID + userId」で、再送しても二重にならない。
- `score` は貢献点(新種 3 / 既発見 1)、`item` は完成品の名前(新種は「(新種)」付き)、`flag` は新種か。抽選エラーのときは記録しない。コメントオートモードの架空のユーザーは記録しない。【案】
- ユーザーの得点(`update-user-stats`)は変えない。
- 既存機能の拡張が必要になる場合は、無理に拡張せず、実装時に改めて検討する。【決定】
